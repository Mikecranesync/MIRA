## Executive Summary

MIRA v3.428 is the **"pilot-ready for the first 5 free 30-day pilots"** milestone. This release hardens the pilot onboarding loop, closes governance gaps discovered in staged testing, and ships the foundational systems for multi-org pilot seat management with approval-required access control.

**Key outcomes:**
- ✅ Approval-required pilot cohort (5 orgs, 5 seats)
- ✅ System-prompt leak guard (Codex #4891 in progress)
- ✅ Free 30-day pilot request form with UTM capture & owner notifications
- ✅ PostHog event tracking for pilot funnel analytics
- ✅ Notebook chat scope reply gate for off-topic questions (trust gate T-5)
- ✅ Checkout endpoint disabled during pilot period (#4369)
- ✅ Reduced attack surface: dropped unused OpenViking dependency (litellm + 5 CVEs)

## Smoke Tests & Verification

### Pre-Deploy Smoke Tests
Run immediately after staging deploy to `staging-vps.yml`:

```bash
# 1. Pilot cohort enforcement
curl -H "Authorization: Bearer $STAGING_AUTH" \
  https://staging.app.factorylm.com/api/pilots/validate-cohort \
  -d '{"count": 5, "org_ids": ["...5 UUIDs..."]}'
# Expected: 200, org count ≤ 5

# 2. Feature flag readiness
curl -H "Authorization: Bearer $STAGING_AUTH" \
  https://staging.app.factorylm.com/api/flags \
  -d '{"flags": ["PILOT_COHORT_5_ORG", "PLG_CHECKOUT_ENABLED"]}'
# Expected: 200, both flags present

# 3. Pilot form submission
curl -X POST https://staging.app.factorylm.com/api/pilot/apply \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","org":"TestOrg","utm_source":"staging"}'
# Expected: 201, application record created

# 4. Notebook off-topic reply
curl -H "Authorization: Bearer $STAGING_AUTH" \
  https://staging.app.factorylm.com/api/notebook/chat \
  -d '{"message": "what is the meaning of life?", "notebook_id": "..."}'
# Expected: 200, response includes isolation notice + T-5 scope reply

# 5. Checkout disabled
curl https://staging.app.factorylm.com/api/checkout/init \
  -H "Authorization: Bearer $STAGING_AUTH"
# Expected: 403 "Checkout disabled during pilot period" (or 200 if PLG_CHECKOUT_ENABLED=true)
```

## Rollback Plan

### Rollback Tag Convention
- **Tag**: `rollback/2026-10-28-v3.428.0`
- **Points to**: The last known-good commit before v3.428 deployment
- **Strategy**: Re-deploy `rollback/2026-10-28-v3.427.0` if critical issues arise

### Rollback Procedure
1. Identify the rollback commit SHA from `rollback/2026-10-28-v3.427.0`
2. Run: `gh workflow run deploy-vps.yml -f approved_rc_sha=<SHA_of_v3.427.0>`
3. Verify smoke tests pass on the rolled-back version
4. Post incident report with findings

### Known Risks & Mitigations
- **Risk**: Pilot cohort enforcement blocking legitimate orgs
  - **Mitigation**: Feature flag `PILOT_COHORT_5_ORG` can be toggled off to disable limit during triage
- **Risk**: PostHog key missing in Doppler
  - **Mitigation**: Analytics will not fire, but service remains functional; pre-deploy Doppler check includes key presence
- **Risk**: New migration 108 fails on staging
  - **Mitigation**: `apply-migrations.yml` has dry-run mode; run `mode=dry-run migrations=108` first
