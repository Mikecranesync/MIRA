## 1. S7-1200: memory card program (PARTIAL)
- **URL:** https://www.plctalk.net/forums/threads/simatic-s7-1200-memory-card-program.125753/
- **Question (verbatim, OP opmal7):** "I have a product that uses a Siemens Simatic s7-1200 PLC. My company did not write the PLC program, but we have the program on an SD card. We usually are working on existing products that are sent to us for repair, and our procedure is to install the SD card, power on the PLC and it loads the program from the card. Once the light blinking is done, the program is loaded and away we go. We are now building the product from scratch, so the PLC has never been powered on before. We tried the same procedure to load the program from the memory card, but didn't have any luck. Does the PLC need to be setup or configured first, before you can load the program from the memory card? If anyone has any helpful articles or youtube videos, I would appreciate it. I have been looking, but haven't found anything yet."
- **Best real answer (BryanG):** No setup is needed, but everything has to match what the card expects. If the CPU firmware is older than the project's, you get an error. Read the diagnostic buffer in TIA, and check whether the red flashing is something else, such as missing analog expansion supply. (mk42: the card must be configured right and the project must match the CPU part number.) There is no confirmed resolution in the thread.
- **MIRA:** The CPU must be in STOP, insert the card, then power-cycle to evaluate it. In RUN the CPU goes to STOP and MAINT flashes. It sees nothing about separate setup being needed. Cites p.114.
- **Grade: PARTIAL.** p.114 is cited correctly (verified: the program-card procedure and the STOP warning). It doesn't diagnose the poster's symptom (lights keep flashing on a new CPU). The manual covers it on p.1047, which MIRA itself cited in the sanity check: flashing red ERROR = memory card error or configuration error (mismatched modules). It also misses the CPU/firmware/part-number match and the diagnostic buffer. Not a reset question.
- **Blog:** no.

## 3. ACS355: A5001 (FAIL)
- **URL:** https://www.plctalk.net/forums/threads/acs355.102851/
- **Question (verbatim, OP salem_gsm):** "I have tried to connect abb acs355 with com cable with pinout on this site posted but after many tries i get a fault code on drive a5001 and i have learned in manual that this is control pannel connection problem how can i solve this problem help me pls"
- **Best real answer:** gclshortt said to enable the serial port ("External serial communication activation" parameter in the user manual). RussB said the onboard RJ-45 is RS-232: 1 TX, 3 RX, 2 and 6 GND. chenken78 later traced a persistent A5001 to a missing 3.3 V at X3 (failed DC-DC converter). The OP did not confirm a fix.
- **MIRA:** "can't verify fault A5001 … excerpts do not include that code." No citations.
- **Grade: FAIL (false abstain).** Manual p.356, "Alarms generated by the basic control panel", lists 5001 "Drive is not responding. Check panel connection." That is verified with pdftotext. The same notebook found fault 0001 on p.359 in the sanity check. The manual has a direct answer, so this is a retrieval miss. Notebook embedding coverage was 0% (lexical only).
- **Blog:** no.
