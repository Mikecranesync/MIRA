1. VERIFIED — In an equipment notebook, MIRA answers from an uploaded OEM manual and cites the page.
2. VERIFIED — On desktop, tapping that citation opens the manual at the cited page. (Not yet proven on phone.)
3. VERIFIED — When the attached manual doesn't cover the question, MIRA says it can't find it there — no citation, no guess.

9. VERIFIED (staging, same build as production) — Upload your plant's manuals, and MIRA answers from them, cites the page, refuses an unsafe shortcut with your manual's own procedure, and tells you honestly when something isn't in what you gave it.

### What we're building (not yet available)
1. PROPOSED — A Work Packet that turns a work order and an equipment photo into a scoped, cited, sign-off-ready job plan with safety and parts called out — each field marked verified / proposed / unknown.
2. PROPOSED — Identifying equipment manufacturer and model from a photo reliably enough to publish as a claim (the mechanism runs today; in the one real test so far it read the model right but misidentified the manufacturer).
3. PROPOSED — Turning a paper measurement sheet (like brake-clearance readings) into a structured, exportable form with pass/fail checks.
4. PROPOSED — Read-only CMMS and PLC/OPC connections, offered only after the free toolkit and team workflows prove useful on their own.
5. PROPOSED — A public, continuously-enforced rule that only proven claims can appear on the website (the registry described in §1, currently in open review as PR #4570).

## 5. Three "see it work" walkthroughs (true today)

**1. Upload a manual → get a cited answer → open the cited page.**
Upload an OEM manual (tested: Rockwell Micro810) to an equipment notebook, ask a plain-English question. The answer names the manual and cites the page; on desktop, tapping the citation opens the manual at that page; if the manual doesn't cover the question, MIRA says so instead of guessing. All three steps are the registry's own `proven` claims (`notebook-cited-answer`, `desktop-citation-opens-page`, `says-when-not-covered`), evidenced by a 2026-10-23 production walk (`punchlist/p1-p7-p8-p9-prod-2026-10-23.md` — a workspace file outside this repo, not independently re-checkable by me here). Caveat the registry itself states: a re-proof on the *current* production build is overdue (#4607); citation tapping is proven on desktop only, not phone.

**2. Upload a CAT Pumps 5CP6120 data sheet and service manual → cited, honest answers.**
On staging, same build as production (v3.427.11 / `1f2ef9695`), a disposable synthetic tenant uploaded the official CAT Pumps 5CP6120 data sheet and service manual through the normal upload path, then asked 6 questions. Result (`docs/evals/2026-10-30-work-packet-5cp6120/staging-results.md`, branch `feat/work-packet-demo-4982`): 5 of 5 technical questions (seal/valve kit counts, oil capacity and interval, torque specs, seal-removal steps, tool list) cited the expected manual page; a request to crack open a pressurized valve was refused, citing the manual's own shutdown procedure; a question about a serial number not in either document was answered honestly ("not shown in the loaded excerpts... send it") with no invented value. This is staging evidence on the production build, not a production re-run, and it is not a T-1 retrieval-benchmark result. The same eval also tried photo identification from the data sheet's image: it got the model (confidence 0.94) but **misread the manufacturer logo** (returned "F.E.T. Pumps" for a CAT Pumps sheet) — which is exactly why photo identification stays PROPOSED and is not part of this walkthrough's claim.

**3. Sign up → account held for an admin to approve.**
`mira-hub/src/middleware.ts::gateRedirect()` redirects any user whose status is `"pending"` to `/pending-approval`, a real page that reads "Your account is under review… An admin will review your request shortly" and polls `/api/auth/check-approval/` until an admin flips the status. This path is feature-flagged (`isPilotApprovalRequired()`, #4878); supporting commit `6a9e8a373` adds "a 5-org cohort and 5-seat cap." **This gate is live in production as of 2026-10-29** (recorded by the coordinator the same day; a signup becomes a pending application, five-company cap, tested on staging) — I did not independently query the live config myself, so I'm relaying that verification rather than re-deriving it. Outside this gated cohort, default self-serve signup instead gets a 30-day trial (`PILOT_WINDOW_DAYS = 30`, not the stale "7-day" figure from the Oct 14 audit).
