## 1. What is compared, and at which stage

| Stage | Fixed input | Candidates |
|---|---|---|
| A. Validator-only | frozen (answer, cited page text) pairs | V0 control, V1 typed verifier, V2 embedding provenance, V3 NLI ×N |
| B. Parser-only | frozen PDF set (sha256 below) | P0 current extraction (`unpdf`-equivalent text layer via `pdftotext -layout`), P1 Docling |
| C. Combined | stage A finalists on stage B text | ablations: V1 alone, V3 alone, V1→V3, V1+V3 on P0 vs P1 page text |

Incompatible candidates never share a stage: Docling is a parser and is never scored as a verifier.

### Evidence for validator-only tests

For every answer, the evidence is **the text of the page(s) it cites**, extracted from the hashed PDF at the cited
1-based physical page (`corpus.json` `pageUnit`). This is exactly H1's question — "does the page it cites support it" —
and avoids pairing an answer with chunks it never saw. The row/window used by V1 is a sub-span of that same text.

### Adversarial set (dev)

Hand-built (answer, cited page) pairs from the PLC-5 manual and the public manuals: bit 11 vs 12 (correct vs
lookalike instruction), `.RLEN = 0`, `.DLEN`, `S:3/10` (absent everywhere), parameter `P09.03` lookalikes
(`P09.30`), fault codes with near neighbours (`ocA`/`ocd`), unit swaps (A vs mA, ms vs s), negation ("is not
reset"), M12 pin numbers, IEC designations (`-K1`, `-Q2`). Each has a hand label (supported / unsupported) and the
reason.

## 3. Split (frozen now; validator rules may only be tuned on DEV)

- **DEV:** the adversarial set + PLC-5 TQ-05/TQ-06 turns + public-50 questions whose id hash is in the lower 30 %
  (`sha256(id) mod 10 < 3`), w1 only.
- **HELD-OUT:** every other public-50 question (all 13 walks), every DEV question's walks w2–w5 / p1 / rr1 / int8,
  real-36 Lane A, Schneider-8. Rules and thresholds are frozen before HELD-OUT is scored; the commit that freezes them is
  recorded in RUNOFF_RESULTS.md.

## 4. Gold and grading

- **Gold facts** (`data/gold.json`): per question, the gold page(s) and the typed key values a correct answer must
  state (e.g. TQ-06 → `.ER`, `bit 12`, condition `.DLEN ≠ .RLEN`), each with a **verbatim quote** that the builder
  checks is present on the gold page's extracted text (fail = gold rejected). Lookalikes that make an answer wrong are
  listed explicitly (TQ-06: `bit 11`, `S:3/10`).
- **Answer label** (deterministic, from gold): `correct_supported` (key values present, a gold page cited),
  `wrong_fact` (a forbidden lookalike or a contradicting typed value stated), `wrong_page` (right fact, no gold page
  cited), `abstain` (honest "not stated"), `ungradable` (prose answer with no typed key value — counted, excluded from
  catch/false-flag rates, never silently dropped).
- **Grader audit:** 40 stratified answers hand-graded by reading answer + page; grader disagreement rate reported.

## 5. Validator scoring (per answer: `supported` | `unsupported` | `no_opinion`)

- **Catch rate** = unsupported ÷ (`wrong_fact` + `wrong_page`).
- **False-flag rate** = unsupported ÷ `correct_supported` (the #4488 failure; weighted as heavily as catch).
- **Coverage** = (supported + unsupported) ÷ all.
- Confusion matrix per validator, per split, numerator/denominator always shown; per-question regressions listed.
- **TQ-06 acceptance (PRD §6):** every `bit 11` answer → unsupported; `bit 12` → supported only when the cited text ties
  bit 12 to `.DLEN/.RLEN`; `S:3/10` → unsupported.
- Latency: p50/p95 per answer on CHARLIE ARM (labelled optimistic — staging x86 under load ran ~5× slower for the
  reranker), peak RSS.

## 6. Parser scoring (stage B)

On the Schneider pinout/parameter pages and the PLC-5 garbled pages: does the gold quote survive extraction (exact,
whitespace-normalised), are table rows kept intact (gold row tokens on one line / one cell group), page attribution
correct, wall time per page, peak RSS. OCR quality on any scanned page in the set.
