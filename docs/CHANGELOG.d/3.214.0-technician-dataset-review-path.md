# v3.214.0 — Technician Dataset v0: paid gate made reachable

Date: 2026-07-25

Makes the Phase-3 paid gate reachable for the technician-grounding LoRA. All work is
offline: no Together call, upload, fine-tune job, endpoint, deployment, authorization
consumption, or spend.

**The gate was structurally unpassable.** `paid_gate.py` requires both `printsense` and
`drive_commander` in the eligible set, but every `drive_commander` candidate was
`public-eval-only` / `training_allowed=false`, so approving one raised
`DECISION_GOVERNANCE_BLOCKED`. No amount of human review could have passed it.

- **OEM training-rights grant** (`docs/zta/2026-07-25-drive-commander-oem-training-rights.md`)
  for `durapulse_gs10` + `powerflex_525` only. **PowerFlex 40 stays blocked** — its lineage
  is 1 of exactly 5 `_HELD_OUT_DOCS` and `MIN_HELD_OUT_LINEAGES == 5`, so granting it would
  shrink the evaluation reserve below the floor. The grant removes the rights block only;
  records still need gold promotion and human approval. The rights *basis* is left for the
  operator to state.
- **cv101 stopped padding duplicates.** `_repeat_to_count` recycles a sheet's facts when the
  target exceeds them: E-008 held 1 fact but targeted 12, E-009 had none so its 10 records
  duplicated E-001, while sheet E-003's 61 owned facts went undrawn. Targets are now capped
  at each sheet's real fact count. Distinct facts in the approvable pool: **42 → 111**.
- **`--import-decisions <jsonl>`** — `--append-decision` takes one file per invocation and
  revalidates the whole set each time. Bulk import runs the same validation and is
  fail-closed (one bad row rejects the batch, ledger untouched) and idempotent.
- **`--model-support-receipt <path>`** — `evaluate_paid_gate` was called with a hardcoded
  `model_support=None` and had no CLI surface. Now threaded through; default stays `None` so
  the gate remains fail-closed. Receipt records a documentation check that `Qwen/Qwen3.5-9B`
  is LoRA-fine-tunable on Together and that pricing ($0.48/Mtok ≤16B, $4.00 minimum) matches
  our pinned constants. Items that could not be verified from primary sources are listed
  rather than assumed.
- **Offline review console** (`tools/factorylm_ai/review_console/`) — single-file, no server,
  no network. Shows only records that can count, puts the answer-key evidence on the card,
  renders a live gate meter against the real thresholds, orders records round-robin across
  lineages, and offers preset rationales (required on every decision). Emits the exact
  `review-decision.v1` shape; its output was accepted unmodified by `--import-decisions`.
- **Candidate build frozen** at manifest `8f4f4f12` (242 entries, 156 approvable). Decisions
  bind to this hash — regenerating candidates invalidates every decision.

Gate status: `model_support_confirmed` now passes; the blocking list is down to the five
review-dependent checks. A dry-run simulation of 110 approvals reaches `PAID_GATE_PASS` on
all 15 checks, proving the path before the review sitting starts. No simulated decision was
written to the repository — the real ledger is empty and awaits human review.
