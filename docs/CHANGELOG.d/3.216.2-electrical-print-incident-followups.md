# v3.216.2 — ELECTRICAL_PRINT incident follow-ups (#2922, #2923)

Date: 2026-07-26

Two follow-ups from the 2026-07-26 print-state bot outage (fixed in v3.215.1, #2921).

**#2922 — `decision_traces` telemetry inserts silently skipped on staging.** Staging's
`decision_traces` table was created by a superseded migration (an older
`user_message`/`final_reply`/`llm_latency_ms` shape), so the canonical column set the engine
writes (`user_question`/`recommendation`/`tag_evidence`/`latency_ms`, per `032_decision_traces.sql`)
was absent → every insert raised `UndefinedColumn` and the trace was dropped. Prod applies
migrations post-merge with no pre-existing draft table, so it has the canonical shape (the §8
silent-`CREATE TABLE IF NOT EXISTS` drift trap). New migration **063** reconciles
**non-destructively + idempotently**: `ADD COLUMN IF NOT EXISTS` the canonical insert-contract
columns, restore `trace_id`'s `DEFAULT gen_random_uuid()`, and drop `NOT NULL` on the superseded
columns the insert never populates (`user_message`, `chat_id`). No `DROP TABLE` (prod-safe;
preserves migration 055). **Verified against the real staging schema** in a rolled-back
transaction — the exact failing insert now succeeds; no-op on a canonical/prod table.

**#2923 — `PrintWorker` crashed on a disabled backend.** Staging/cloud-only points
`openwebui_url` at a `disabled://` sentinel; `PrintWorker.process` posted to it and httpx raised
`unsupported protocol`, surfacing as `GENERIC_ENGINE_ERROR`. `process()` now detects a non-http(s)
endpoint and returns a graceful notice (`PRINT_BACKEND_UNAVAILABLE_MESSAGE`) — a disabled optional
backend fails soft.

Tests: `mira-bots/tests/test_print_worker_disabled_backend.py` (6, green); 121 adjacent print tests
pass.
