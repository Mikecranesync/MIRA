# v3.216.2 — ELECTRICAL_PRINT incident follow-ups (#2922, #2923)

Date: 2026-07-26

Two follow-ups from the 2026-07-26 print-state bot outage (fixed in v3.215.1, #2921).

**#2922 — `decision_traces` telemetry inserts silently skipped on staging (+ broader staging
schema-drift reconciliation).** The persistent staging Neon branch has tables created by
**superseded** migrations: because canonical migrations use `CREATE TABLE IF NOT EXISTS`, they
skipped re-creation over the pre-existing stale tables, so staging diverged from the repo while the
ledger reported "applied" (the §8 silent-drift trap). The engine writes the canonical
`032_decision_traces.sql` column set (`user_question`/`recommendation`/`tag_evidence`/`latency_ms`),
which the drifted staging table lacked → every insert raised `UndefinedColumn` and the trace was
dropped. Running the migration integration tests also surfaced a second drifted table
(`flaky_input_signals`, missing `source_tag_path`). Prod applies migrations post-merge with no
pre-existing draft table, so it has the canonical shape — **every statement in 063 is a no-op on a
canonical/prod table.**

New migration **063** reconciles both:
- **`decision_traces` — additive, non-destructive:** `ADD COLUMN IF NOT EXISTS` the canonical
  insert-contract columns, restore `trace_id`'s `DEFAULT gen_random_uuid()`, relax `NOT NULL` on the
  superseded columns the insert never populates (`platform`, `user_message`, `chat_id`). No
  `DROP TABLE` (preserves migration 055).
- **`flaky_input_signals` — guarded drop + recreate to canonical 034:** the wholesale-different
  superseded shape is replaced with the canonical table only when `source_tag_path` is absent
  (a Phase-9 detector table carrying only stale staging rows); the guard makes it a no-op on prod.

**Verified against the real staging schema** in a rolled-back transaction — both RLS integration
tests' exact inserts (`decision_traces`, `flaky_input_signals`) now succeed; migration-verify
applies + regression-tests it on the PR.

**#2923 — `PrintWorker` crashed on a disabled backend.** Staging/cloud-only points
`openwebui_url` at a `disabled://` sentinel; `PrintWorker.process` posted to it and httpx raised
`unsupported protocol`, surfacing as `GENERIC_ENGINE_ERROR`. `process()` now detects a non-http(s)
endpoint and returns a graceful notice (`PRINT_BACKEND_UNAVAILABLE_MESSAGE`) — a disabled optional
backend fails soft.

Tests: `mira-bots/tests/test_print_worker_disabled_backend.py` (6, green); 121 adjacent print tests
pass.
