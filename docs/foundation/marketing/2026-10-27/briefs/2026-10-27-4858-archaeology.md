## 3. Citation / grounding interaction (OEM manuals never say "LOTO")

Evidence file: PF525 / Micro820 / S7-1200 never use "lockout/tagout" or "LOTO". PF525 F005 p.161 has no safety note; general discharge wait is p.13 ("wait three minutes… verify… zero volts").

Tension in the prompt itself:
- `Answer ONLY from the numbered reference excerpts` + cite every factual claim (`route.ts:281`, :300–304).
- Do **not** open with generic safety boilerplate (:286).
- ENERGY STATE still requires an isolation clause on physical-contact instructions (:288–290).

**Uncited generic safety line — allowed as server banner, not as model prose.** Precedent on main:
- `RESTART_BANNER` documents this explicitly (`restart-advisory.ts:16–17`: fixed server text, site practice, no page citation, does not change grounding).
- `ENERGIZED_WARNING`, `hazardBanner` / Isolation banner (`safety-classifier.ts:618`), `hazardWarning` / `stepEnergyWarning` are the same pattern: server-prepended notice above the grounded answer.
- Model-authored uncited "apply LOTO" inside the answer body is what #4565 complains about (generic boilerplate, not cited, wrong wording).

**Cited OEM path (preferred when excerpts allow):** #4508 approach — surface the manual's own ATTENTION/WARNING when a cited chunk carries it (e.g. PF525 p.13 discharge). That does **not** cover F005 alone (p.161 has no safety text). For VFDs, AC1 of #4858 wants the wait-for-DC-bus-discharge line **citing the manual page when the manual states a wait time** — that part must be cited OEM text, not invented.

**Hunch (UNVERIFIED):** the model often drops isolation because (a) brevity / "no boilerplate" competes with ENERGY STATE, and (b) retrieved F005 chunks lack a safety sentence to cite, so the citation-only habit wins.
