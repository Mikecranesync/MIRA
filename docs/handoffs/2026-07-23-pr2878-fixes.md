# PR 2878 Fix Handoff

PR #2878 is green-ish but should not merge until these dataset/paid-gate fixes land.

## 1. Manifest Must Hash Training Content

File:

- `factorylm_ai/dataset/record.py`

Problem: `to_manifest_entry()` uses `candidate.evidence_id or self.content_hash()` as `content_hash`. If a source has an evidence hash, changed training `messages` can produce the same manifest hash.

Fix:

- always use `self.content_hash()` for the manifest `content_hash`
- keep source evidence separately if needed, for example `source_evidence_id`
- add a regression test proving changed `messages` change `manifest_sha256` even when `candidate.evidence_id` is unchanged

## 2. Paid Gate Must Revalidate Dataset Eligibility

Files:

- `factorylm_ai/dataset/assemble.py`
- `factorylm_ai/dataset/paid_gate.py`

Problem: `evaluate_paid_gate()` trusts `DatasetV0.eligible`. A manually constructed `DatasetV0` can include unapproved or governance-ineligible records and still pass if counts/rights/splits look good.

Fix:

- add a `DatasetV0.invalid_eligible_records()` helper, or equivalent internal check
- require every record in `dataset.eligible` to satisfy `record.is_dataset_eligible()`
- add a gate check such as `all_records_dataset_eligible`
- add tests proving unapproved and governance-ineligible records in `eligible` block the paid gate

## 3. Cost Override Must Not Understate Known Tokens

File:

- `factorylm_ai/dataset/paid_gate.py`

Problem: passing both `train_tokens` and a low `est_cost_usd` lets the caller bypass the cost cap. Example: `train_tokens=50_000_000, est_cost_usd=0.01` can pass.

Fix:

- if `train_tokens` is provided, compute cost from tokens and ignore `est_cost_usd`, or
- use `max(est_cost_usd, estimate_finetune_cost(train_tokens, epochs=epochs))`
- add a regression test proving over-cap `train_tokens` blocks even with a low supplied estimate

## 4. Align Paid-Gate Thresholds With The Tightened Spec

File:

- `factorylm_ai/dataset/paid_gate.py`

Problem: the parent plan's addendum tightens the initial content target to `>=20` independent lineages, but PR #2878 keeps `MIN_LINEAGES = 15`.

Fix:

- set `MIN_LINEAGES = 20`
- update passing/failing fixtures accordingly

## 5. Add Missing Readiness Evidence Checks

Files:

- `factorylm_ai/dataset/record.py`
- `factorylm_ai/dataset/assemble.py`
- `factorylm_ai/dataset/paid_gate.py`

Problem: the tightened target also requires `>=5` held-out lineages, `>=15` safety-sensitive examples, PrintSense + Drive Commander + SimLab/MIRA representation, synthetic composition disclosure, and base-vs-tools benchmark evidence. PR #2878 only checks no held-out contamination, not readiness coverage.

Fix:

- track source-system composition from `record.candidate.source_system`
- count safety-sensitive records via an explicit tag or field, not free-form inference
- include a paid-gate input/evidence object for:
  - held-out lineage count
  - synthetic composition disclosed
  - base-vs-tools benchmark complete
- add gate checks for each required evidence item
- add one blocked test per new check

## 6. Model Support Confirmation Needs Evidence, Not Just A Boolean

File:

- `factorylm_ai/dataset/paid_gate.py`

Problem: `model_support_confirmed=True` is enough to pass the model-support check, with no evidence/provenance.

Fix:

- replace or supplement the boolean with a small evidence object, for example `ModelSupportEvidence(model_id, provider, checked_at, method, supported)`
- pass only when `supported is True` and required evidence fields are present
- keep this pure: no network call here
- add tests for missing evidence, unsupported model, and supported evidence
