# M001 observation state — deviations from TASK.md

Each entry: what TASK.md said, what was done, and why.

1. **Postgres socket path.** Data dir is under the scratchpad as TASK.md asks (`.../scratchpad/m001/pg`), port 55433 over TCP. The Unix socket directory is `/tmp/m001sock` because the scratchpad path exceeds macOS's 103-byte socket limit (initial start failed: "could not create any Unix-domain sockets"). Tests connect to `127.0.0.1:55433` only.
2. **Dependencies.** `mira-hub/node_modules` was absent; ran `npm ci` inside this worktree (lockfile install). Nothing copied from another checkout.
3. **Typecheck.** There is no `typecheck` script in `mira-hub/package.json`. Used `npx tsc --noEmit -p tsconfig.json`. Base (origin/main, before any edit) has 134 pre-existing errors (mostly `packages/factorylm-ui` missing React types). After the change the error set is byte-identical (`diff` of sorted error lines is empty).
4. **Store signature.** TASK: `insertObservation(tenantId, notebookId, expectedEntityId, input, recordedBy, deps?)`. Done: `insertObservation(tenantId, notebookId, expectedEntityId, assetUnsPath, input, recordedBy, deps?)`. `asset_uns_path` is the server binding's `unsPath` (from `resolveBoundAsset`), not derived from `source_turn_id`, because the turn is optional.
5. **Shared helpers in `cmms-dispatch/enqueue.ts`.** Extracted `lockAggregate(c, key)` and `nextAggregateSequence(c, key)` as exports; fix path calls them in the same order (lock first, then sequence). No fix behaviour change; `dispatcher.integration.test.ts` 38/38 green after the change.
6. **One bound notebook per asset.** TASK's readback test assumes a "second notebook" bound to the same asset. Migration 081 has `UNIQUE (tenant_id, equipment_entity_id) WHERE equipment_entity_id IS NOT NULL`, so two notebooks cannot be bound to one machine at once. The test models a handover (notebook A releases the machine, notebook B binds it). The readback is still scoped by asset, not notebook.
7. **`supersedes_id` FK action.** TASK did not specify. `ON DELETE SET NULL`, not NO ACTION: a superseding row may sit in another notebook of the same asset, and NO ACTION would make deleting the older notebook fail (breaking `deleteNotebook`).
8. **Status-to-HTTP mapping on POST.** `source_turn_not_found` → 400 (the listed codes in TASK have no 404 for it). `supersedes_not_found` → 409. `binding_changed` → 409 `asset_binding_changed`.
9. **Readback when unbound or unconfirmed.** TASK silent. GET returns 409 `asset_not_bound` / `asset_not_confirmed`, matching POST and preview.
10. **Flag value.** `MIRA_OBSERVATION_STATE` is on only for `"1"` or `"true"`. Read at call time (`flag.ts`).
11. **Evidence frame typing.** `NotebookBasisEvidenceFrame` lives in `src/lib/notebook-chat-types.ts`, a guarded legacy path, so it was not edited. The route attaches `observedState` with `Object.assign` (`chat/route.ts`).
12. **Readback content.** `listObservationsForAsset` returns `rawReport` (the technician's own confirmed words for that observation) in history rows. It does NOT return the notebook id, source turn id, request fingerprint, or any chat thread. If "thread content" was meant to include `rawReport`, drop that one column from `RECORD_COLS`.
13. **Seal vocabulary.** TASK's "seal + leak/drip/weeping" would miss "no leak seen" (no "seal" word) and "replaced the seal" would mis-fire. `seal_leak` matches a bare `seal(s)` or a `leak/drip/weep` word, so the TASK examples resolve as written.
14. **Plant time zone.** TASK did not name one. Preview uses `America/New_York` (Lake Wales, FL). The chat consumer reads no time.
15. **Chat test store seam.** TASK suggested stubbing `withTenantContext`. The field-observation harness stubs it to return `undefined`, which makes "table missing" and "no rows" indistinguishable. The chat test mocks `@/capabilities/observations/store` directly instead.
16. **Route test DB seam.** Route tests mock the store module (the DB edge), not `pg`. Store behaviour is covered by the real-Postgres integration test.
17. **Flag-off byte identity.** TASK asks "flag off → prompt byte-identical to baseline". No pre-change baseline exists in code, so the test compares the flag-off prompt with a flag-on prompt whose store returns zero rows (both must be identical) and asserts the store is never called when the flag is off.
18. **Migration apply.** `db/proposed/113_asset_observations.sql` is applied by the integration `beforeAll` twice (idempotency). Not copied into `db/migrations/`.
19. **Not verified here.** Lifecycle guard run (`tools/ui_surface_lifecycle_guard.py`), Codex exact-head review, staging `migration-verify`, prod, `ci-wait`. The chat route edit is a guarded path, so the PR body needs a `## Lifecycle guard rationale` section before merge.
