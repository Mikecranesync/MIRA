## FINDINGS
- **[severity: high] Host canonicalisation uses `lower()` instead of Unicode‑aware case folding, allowing case‑variant Unicode hostnames to be stored as distinct keys**  
  `mira-crawler/ingest/provenance.py` (and the same logic in `mira-crawler/ingest/store.py`):  
  ```diff
  ++    scheme = _up(url).scheme.lower()
  ++    host = (urlparse(str(url)).hostname or "").lower()
  ```  
  The RFC 3986 host component is case‑insensitive **and** must be compared in a Unicode‑aware manner (IDNA 2008). Using `str.lower()` does not normalise characters such as the German sharp‑s (ß → ss) or other locale‑dependent case mappings, nor does it perform the required punycode conversion for Internationalised Domain Names. Consequently two URLs that differ only by Unicode case (e.g. `https://ExÄmple.com/doc` vs `https://exäMple.com/doc`) will be stored under different `source_url` values. Because visibility (`enforce_visibility`) is decided per row after the host is lower‑cased, one row may be treated as curated (if a policy entry matches the lower‑cased form) while the other remains uncurated, creating a **privacy‑exposure** gap and duplicate‑storage defect that the PR does not address.

- **[severity: medium] Percent‑encoding normalisation does not apply to the *authority* portion of a URL**  
  `mira-crawler/ingest/provenance.py` (function `_credential_query_name`):  
  ```diff
  ++    for stop in "/?#":
  ++        authority = authority[:idx]
  ++    return "@" in authority
  ```  
  The function extracts the authority string before normalising percent‑encoded characters. A URL such as `https://example.com/%41uth` (where `%41` decodes to `A`) retains the encoded form in the authority check, meaning the presence of a userinfo token encoded as `%40` (the `@` character) would be missed. This permits credential‑bearing URLs with percent‑encoded `@` in the authority to bypass the userinfo refusal, violating the documented “any `@` in a `scheme://authority` is refused”. While the current test suite covers a few cases, the omission of authority‑level percent‑decoding is a security regression.

## NOT REVIEWED
- The impact of Unicode host case‑folding on downstream policy lookup (e.g. whether a lower‑cased host that was case‑folded differently would still match an entry in `provenance_policy.yaml`).  
- Whether existing database rows already contain Unicode‑variant host keys and how the new guard would affect deduplication in practice.  
- Potential interactions with the `canonical_source_url` function’s handling of Unicode normalization for path, query, and fragment components, which are intentionally left byte‑exact. Further testing would be required to confirm no unintended visibility differences arise from those components.
