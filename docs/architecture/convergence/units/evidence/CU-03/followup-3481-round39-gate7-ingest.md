## FINDINGS
- **[severity: high] `ingested_source_urls` now silently rejects calls with an empty or whitespace‑only `tenant_id`, breaking any existing workflow that relied on the historic “no‑tenant” probe to query across all tenants.**  
  The new guard added in `mira-crawler/ingest/store.py` short‑circuits the function before any SQL is issued:

  ```diff
  +    if not isinstance(tenant_id, str) or not tenant_id.strip():
  +        # Fail closed — a empty, None, whitespace-only or non-string is not a
  +        # tenant. (A whitespace tenant would still be scoped — `tenant_id = ' '`
  +        # matches no row — but it is invalid input and must not reach SQL.) (Gate 7 round M on #3481): without a tenant this probe
  +        # would have queried EVERY tenant's rows. Nothing is reported as
  +        # ingested, so ledger items stay pending — the retryable direction.
  +        logger.warning("ingested_source_urls called without a tenant_id — refusing the probe")
  +        return set()
  ```

  Previously the function built the query without a `tenant_id` filter when the argument was empty, allowing a caller to discover which URLs existed *across all tenants* (a documented feature used by the ledger probe).  Re‑introducing this validation reverts that capability and will cause any existing code path that calls `ingested_source_urls` with the default `tenant_id=""` to always receive an empty result set.  The symptom is duplicated ingestion attempts, wasted crawl work, and potential ledger dead‑locks.  Because the regression re‑opens a previously adjudicated behavior and can affect large‑scale ingestion pipelines, it is a high‑severity defect.

- **[severity: high] Credential‑query‑parameter detection can be bypassed by embedding a Unicode diacritic (or any non‑ASCII alphanumeric) in the name, because the folding logic strips only ASCII `[0‑9a‑z]` characters after NFKC normalisation.**  
  The detection code introduced in `mira-crawler/ingest/provenance.py` defines the “noise” regex and folding function as:

  ```diff
  +_CREDENTIAL_QUERY_NAMES = frozenset(
  +    {
  +        "token",
  +        "accesstoken",
  +        ...,
  +        "xgoogcredential",
  +    }
  +)
  +_QUERY_NAME_NOISE_RE = re.compile(r"[^0-9a-z]")
  ```

  ```diff
  +def _fold_query_name(raw: str) -> str:
  +    """The comparison key of a query-parameter name: percent-decoded, NFKC,
  +    lower-cased, every non-alphanumeric character removed. Pure."""
  +    from unicodedata import normalize
  +    from urllib.parse import unquote
  +
  +    return _QUERY_NAME_NOISE_RE.sub("", normalize("NFKC", unquote(raw)).lower())
  ```

  Because `_QUERY_NAME_NOISE_RE` retains **only ASCII digits and letters**, any Unicode letter (including diacritics such as “á”, “ö”, or full‑width letters that NFKC already maps to ASCII) is stripped away.  An attacker can therefore construct a URL like:

  ```
  http://example.com/?p%C3%A1ssword=secret
  ```

  After percent‑decoding `p%C3%A1ssword` → `pássword`, NFKC leaves the “á” unchanged, lower‑casing yields `pássword`, and the noise regex removes the “á”, resulting in `pssword`.  This folded name does **not** match any entry in `_CREDENTIAL_QUERY_NAMES`, so the URL slips past `_credential_query_name` and is accepted as safe, even though it carries a credential‑family parameter.  The same bypass works with any Unicode alphanumeric character inserted anywhere in the name (e.g., `pássword`, `pаssword` with a Cyrillic “а”, etc.).  This is a security‑critical bypass that the original design intended to prevent, and it was the subject of the earlier “Unicode alphanumeric bypass in credential‑query‑parameter detection” finding (round 3).  The current implementation re‑introduces the vulnerability, so it must be considered a high‑severity defect.

## NOT REVIEWED

- Interaction of `canonical_source_url` with Internationalised Domain Names (IDNs) that are not punycode‑encoded; the function lower‑cases the Unicode host but does not perform IDNA conversion, which could lead to duplicate rows for the same domain represented with different Unicode normalisations.  
- Performance impact of the expanded `ANY(:urls)` array query in `chunk_exists` and `ingested_source_urls` on very large batches; the test suite does not currently stress this path.

- Behaviour of `canonical_source_url` on malformed but scheme‑like strings (e.g., `C://path`) and on URLs containing IPv6 zone identifiers; these edge cases are not covered by existing unit tests.
