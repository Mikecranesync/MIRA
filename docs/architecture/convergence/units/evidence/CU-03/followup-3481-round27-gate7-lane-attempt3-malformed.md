### 1.  `drop_evidence_artifacts` does **not** drop renamed evidence artefacts  
**Location:** `tools/gate7_review.py` – function `drop_evidence_artifacts` (lines ≈ 920‑945).  

```python
source, _, target = header.rpartition(" b/")
# … 
moved_artifact = is_evidence_artifact(source) and target.lower().endswith(_DOC_SUFFIXES)
keep = not (is_evidence_artifact(target) or moved_artifact)
```

*Problem*  
The `source` string still contains the leading `"a/"` that is present in every diff header (`diff --git a/... b/...`).  
`is_evidence_artifact` expects a plain repository‑relative path that starts with `_EVIDENCE_DIR`.  
Consequently `is_evidence_artifact(source)` is **always False** for a rename, even when the *original* file lives under `docs/…/units/evidence/`.  

The result is that a file that was originally an evidence artefact but is **renamed** to another location (e.g. `docs/notes/round‑9‑review.md`) is **kept** in the diff and therefore visible to the reviewer.  The contract (see the doctrinal “evidence‑artifact” section) requires *every* preserved evidence artefact to be excluded **irrespective of the rename target** and to be listed in the receipts.  

*Evidence* – the test `test_preserved_evidence_artifacts_are_dropped_from_the_reviewed_diff_and_receipted` expects:

```python
assert dropped2 == ["docs/notes/round-9-review.md", e + "plain.md"]
```

but the current implementation returns `dropped2 == []` (the rename is kept).  

*Impact*  
- A malicious PR could smuggle historical reviewer output (raw model replies, log files, etc.) into the reviewed diff simply by renaming the file out of the `units/evidence/` tree.  
- The receipts will *not* mention the artefact, breaking the “audit‑trail” guarantee.  
- This is a direct violation of the **tenant‑scoping / evidence‑exclusion** security boundary.

*Fix*  

```python
# Strip the leading "a/" before the artefact test
src_path = source[2:] if source.startswith("a/") else source
# An artefact is dropped if either the target lives in the evidence dir
# OR the *original* path was an artefact and the rename stays a doc‑suffix file.
moved_artifact = is_evidence_artifact(src_path) and target.lower().endswith(_DOC_SUFFIXES)
keep = not (is_evidence_artifact(target) or moved_artifact)
if not keep:
    dropped.append(target)          # record the *new* path as the excluded artefact
```

This change makes the rename‑to‑doc‑suffix case drop the artefact (as the test expects) while still **keeping** a rename that turns a `.log` artefact into code (`.py`), which the spec explicitly allows.

### 2.  File‑extension checks are **case‑sensitive** – PR‑kind mis‑classification  
**Location(s):**  

* `pr_kind` (lines ≈ 288‑301)  

```python
if any(path.endswith(_DOC_SUFFIXES) for path in changed_paths):
    return "mixed"
```

* `is_evidence_artifact` (lines ≈ 1022‑1034)  

```python
if not path.startswith(_EVIDENCE_DIR):
    return False
name = path.rsplit("/", 1)[-1].lower()
if not name.endswith(_DOC_SUFFIXES):
    return False
```

*Problem*  
Both checks use `str.endswith` **without** normalising case.  On case‑preserving filesystems (e.g. Windows, macOS with case‑preserving but case‑insensitive FS) a file such as `README.MD` or `Docs/CHANGES.TXT` will **not** be recognised as documentation.  The PR will then be classified as `"code"` instead of `"mixed"` or `"documentation"`.

*Why it matters*  

1. The **decision‑point reminder** (`decision_point_reminder`) is only injected for `"documentation"` or `"mixed"` PRs.  A mixed PR mis‑classified as `"code"` will lose the reminder, re‑exposing the “historical EVIDENCE” block to the reviewer (the bug that motivated the reminder in the first place).  

2. The **receipt block** (`receipts_block`) lists excluded evidence artefacts only when `artifacts` is non‑empty.  If the artefact’s filename uses an upper‑case suffix, it will be missed by `drop_evidence_artifacts` (which calls `is_evidence_artifact`) and will erroneously become part of the reviewed diff.  This is a direct tenant‑leakage vector.

*Impact* – Mis‑classification can lead to **false‑negative** security warnings, allowing evidence artefacts to be reviewed as if they were author‑written code.

*Fix* – Normalise the path before the suffix test:

```python
if any(path.lower().endswith(_DOC_SUFFIXES) for path in changed_paths):
    return "mixed"
```

and similarly in `is_evidence_artifact` (the `name` variable is already lower‑cased, but the `path.startswith(_EVIDENCE_DIR)` comparison should also be case‑insensitive for completeness):

```python
if not path.lower().startswith(_EVIDENCE_DIR.lower()):
    return False
```

These two‑line changes make the kind detection fully case‑insensitive and bring the implementation back in line with the doctrinal expectation that file‑extension handling is case‑agnostic (see the “Percent‑encoding case is not normalised” finding in earlier rounds).

### 4.  Minor – `_strip_fences` may mis‑strip fenced blocks with language tags  

**Location:** `tools/gate7_review.py` – function `_strip_fences` (lines ≈ 1245‑1265).

The current implementation treats any line that matches `^\s*(```|~~~).*?$` as a fence delimiter, toggling on the first occurrence and off on the next line that *starts with the same marker*.  When a code block starts with a language tag (` ```python `) the opening marker is captured as ````````, but the closing line is usually just ````````, which still satisfies `startswith("```")`.  The logic works for the common case, but it will **mistakenly close a fence early** if a fenced block contains another line that begins with the same three backticks (e.g. a literal string ``````` inside a markdown quote).  The side‑effect is that the quoted fence content is stripped, potentially exposing hidden headings to the shape validator.

*Impact* – An adversarial reviewer could embed a line that begins with ``````` inside a fenced block to *un‑fence* the rest of the reply, causing spurious `## VERDICT` or `## RULINGS` headings to be interpreted as structural sections.  This would turn an otherwise **UNKNOWN** output into a **PASS/BLOCK** and defeat the “strict‑shape” guarantee.

*Mitigation* – Use a proper fence state machine that remembers the exact fence marker (including any language tag) and only closes when a line consisting **solely** of that marker (optionally followed by whitespace) appears:

```python
if m:
    fence = m.group(1)
    if inside is None:
        inside = fence          # opening fence (store the full marker, e.g. "```python")
    elif line.lstrip().startswith(inside.split()[0]):   # closing fence must match the opening marker *without* language spec
        inside = None
    # replace the fence line with a blank line to preserve line numbers
    out.append("\n")
    continue
```

While the current test suite does not hit this edge case, it is a realistic adversarial vector that the Gate 7 brief explicitly guards against (see the “headings inside fenced code blocks are not sections” test).  Fixing it now prevents a future regression.
