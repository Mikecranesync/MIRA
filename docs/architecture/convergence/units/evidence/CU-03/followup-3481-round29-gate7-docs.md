## FINDINGS
- **[severity: high] Over‑blocking of legitimate IPv6 URLs with zone identifiers** – The new `url_has_userinfo` implementation in `mira-crawler/ingest/provenance.py` rejects any URL that contains a userinfo component by checking the parsed authority. The function is defined as:
  ```python
  def url_has_userinfo(url: str) -> bool:
      """Reject any scheme://authority with userinfo."""
      parsed = urlparse(url)
      return parsed.username is not None
  ```
  IPv6 literals that include a zone identifier (e.g. `http://[fe80::1%eth0]/`) are valid per RFC 4007, but `urlparse` treats the `%` as the start of a percent‑escape and fails to populate `username`. Consequently, the function erroneously interprets the presence of `%` in the authority as userinfo and returns `True`, causing the URL to be refused before any SQL or logging occurs. This false positive blocks legitimate ingestion of IPv6‑zone URLs, reducing availability of correctly scoped data and potentially breaking downstream workflows that rely on such URLs.

- **[severity: medium] Missing test coverage for IPv6 zone‑identifier URLs** – The test suite added in this PR (`tests/test_provenance_policy.py` and related files) covers userinfo rejection for common schemes (http, https, ftp, s3, etc.) but does not include a case for IPv6 URLs with a zone identifier. Without a dedicated test, the regression described above can go unnoticed, allowing the over‑blocking bug to persist in production.
