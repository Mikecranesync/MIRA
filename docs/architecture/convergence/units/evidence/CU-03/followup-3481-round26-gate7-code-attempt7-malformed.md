## Raw review

**Summary**

The recent “case‑insensitive origin discovery” and “canonical URL” overhaul is solid, but one critical contract is broken: **`ingested_source_urls()` no longer returns the caller‑supplied spelling of a URL that is present in the database**. The function now returns the raw `source_url` values stored in `knowledge_entries`. When a row was stored using the *canonical* spelling (the new default) the ledger probe returns the canonical spelling instead of the original string that the caller asked about. This violates the contract exercised by the extensive `TestCanonicalSourceUrl` suite (e.g. `test_ledger_probe_matches_historical_port_and_escape_spellings` and `test_ledger_probe_matches_canonical_and_historical_rows_in_the_callers_spelling`) and can cause **duplicate ingestion** under a mixed‑case or default‑port URL. The bug is hidden from the existing test suite because the tests mock the DB rows and only check the return value, not the intermediate query.

Below is a concise description of the defect, its impact, and a minimal, well‑scoped fix.

---

### 1. Defect Details

**Location** – `mira-crawler/ingest/store.py`

```python
def ingested_source_urls(source_urls: list[str], tenant_id: str = "") -> set[str]:
    ...
    lookup = sorted({*asked, *(canonical_source_url(u) for u in asked)})
    try:
        with _engine().connect() as conn:
            rows = conn.execute(
                text(
                    "SELECT DISTINCT source_url FROM knowledge_entries "
                    "WHERE source_url = ANY(:urls) AND tenant_id = :tid"
                ),
                {"urls": lookup, "tid": tenant_id},
            ).fetchall()
        return {r[0] for r in rows if r and r[0]}
    ...
```

**Expected contract (see `TestCanonicalSourceUrl`):**

* The function must *answer in the caller’s own spelling*.
* For a canonical row (`https://example.com/New%7A.pdf`) queried with the raw spelling
  (`https://example.com:443/New%7a.pdf`) the function must return the **raw** string,
  not the canonical one.
* The same applies to historical rows that were stored with their original (non‑canonical) spelling.

**Current behaviour:**  
The set comprehension `{r[0] for r in rows …}` returns exactly what the DB returned. When the DB only has the canonical spelling, the caller receives the canonical value, breaking the “answer in the caller’s own spelling” contract.

**Consequences**

1. **False‑negative ledger probes** – the ledger thinks a URL has *not* been ingested because the raw spelling is not present in the result set, even though the canonical row exists.
2. **Duplicate ingestion** – a later crawl that supplies the raw spelling will treat it as “missing” and insert a second row, violating the uniqueness guarantee enforced by the `idx_ke_chunk_dedup` index.
3. **Incorrect reporting** – the `ingested_source_urls` function is used by the “ledger probe” (`ingest_ledger.reconcile`). Incorrect results propagate to downstream KG linking, potentially causing duplicate KG entities and noisy alerts.
4. **Test regression** – the two failing tests in `tests/test_gate7_review.py` (`test_ledger_probe_matches_historical_port_and_escape_spellings` and `test_ledger_probe_matches_canonical_and_historical_rows_in_the_callers_spelling`) currently pass only because the implementation was accidentally left unchanged in the original code base; after the new tests were added they now expose the regression.

---

### 2. Fix Proposal

Rewrite `ingested_source_urls` to:

1. Perform the same *dual‑lookup* (raw + canonical) as before.
2. Build a **set of rows returned by the DB**.
3. Map each *asked* URL to the caller’s spelling **iff** either the raw or canonical form appears in the DB result set.
4. Return the set of caller‑supplied URLs that matched.

```python
def ingested_source_urls(source_urls: list[str], tenant_id: str = "") -> set[str]:
    """Return which of ``source_urls`` actually have rows in knowledge_entries.
    The returned URLs are **exactly the strings the caller supplied** – even
    when the row was stored under the canonical spelling.
    """
    if not source_urls:
        return set()

    # Reject malformed / missing tenant – fail‑closed (Gate 7 round M).
    if not isinstance(tenant_id, str) or not tenant_id.strip():
        logger.warning(
            "ingested_source_urls called without a tenant_id — refusing the probe"
        )
        return set()

    from sqlalchemy import text

    # -----------------------------------------------------------------
    # Build the lookup set: every raw spelling *and* its canonical form.
    # -----------------------------------------------------------------
    asked = list(source_urls)
    asked = [u for u in asked if not _refuse_userinfo(u)]
    if not asked:
        return set()

    lookup = sorted({*asked, *(canonical_source_url(u) for u in asked)})

    try:
        with _engine().connect() as conn:
            rows = conn.execute(
                text(
                    "SELECT DISTINCT source_url FROM knowledge_entries "
                    "WHERE source_url = ANY(:urls) AND tenant_id = :tid"
                ),
                {"urls": lookup, "tid": tenant_id},
            ).fetchall()
    except Exception as exc:  # pragma: no cover – defensive
        logger.warning("ingested_source_urls check failed (treating as none): %s", exc)
        return set()

    # -----------------------------------------------------------------
    # ``stored`` holds every source_url the DB knows about (canonical or
    # historical).  For each caller‑provided URL we answer *yes* if either
    # the raw value or its canonical form is present in ``stored``.
    # -----------------------------------------------------------------
    stored = {r[0] for r in rows if r and r[0]}
    matched = {
        raw for raw in asked
        if raw in stored or canonical_source_url(raw) in stored
    }
    return matched
```

**Why this change is safe**

* **No behavioural change for existing callers** – callers have always expected the function to answer “yes/no” for the URLs they asked about. Returning the raw string (instead of the canonical one) is a *strict* superset of the previous behaviour.
* **Preserves the dual‑lookup optimisation** – we still query for both raw and canonical values; the only addition is a lightweight set‑lookup in Python.
* **Maintains existing security checks** – user‑info URLs are filtered out before any DB interaction, exactly as before.
* **Preserves error‑handling semantics** – any DB exception still results in a warning and an empty set, matching the previous contract.

---

### 3. Additional Recommendations (not strictly required for the current regression)

1. **Add a unit test for the empty‑URL edge‑case.**  
   `store.insert_chunk` currently accepts an empty `source_url` and will store a row with an empty string. This can lead to cross‑tenant conflicts (the unique index includes `tenant_id` but an empty string is a valid value). A defensive guard (`if not source_url: return ""`) would make the behaviour explicit and prevent accidental ingestion of “no‑source” rows.
2. **Document the “answer in the caller’s own spelling” guarantee** in the docstring of `ingested_source_urls` (already added above) and in the architectural design notes, because this subtle contract is critical for ledger correctness.
3. **Run the full test suite with the new implementation** – the two failing tests mentioned above should now pass, and all existing tests remain green.
