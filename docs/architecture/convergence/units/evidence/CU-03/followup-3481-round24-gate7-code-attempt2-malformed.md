## Summary  

The PR introduces a sophisticated *canonical‑URL* implementation in `mira‑crawler/ingest/store.py` together with a matching change to `chunk_exists` and `ingested_source_urls`.  The intent is to guarantee that the *deduplication key* `(tenant_id, source_url, chunk_index)` is **case‑insensitive** for scheme/host and normalises default ports and percent‑escapes.

The implementation is **almost correct**, but **fails to normalise the empty‑path ↔ single‑slash equivalence** (i.e. `"https://example.com"` vs. `"https://example.com/"`).  This edge‑case is **not exercised by the new test‑suite** and was **missed by both the author’s corpus‑based fuzzing and the generated fuzz corpus**.  

Because the unique index on `knowledge_entries` is **exact‑match on `source_url`**, the missing normalisation enables **duplicate rows for the same logical document**.  The duplicate may be created:

* **During ingestion** – two different crawls of the same URL, one with a trailing slash and one without, will each succeed and store separate rows.  
* **During ledger probing** – `ingested_source_urls` will report only the exact spelling it was asked about, so a pending ledger item that supplies the slash‑variant will never be cleared, leading to **infinite retry loops**.  

Both behaviours are **high‑severity regressions**: they break the deduplication guarantee, inflate storage, and can leak private‑visibility flags across duplicate rows (the “private‑visibility never upgraded on conflict” guarantee is predicated on a single row per logical document).

## Overall Verdict  

**BLOCK** – the PR **fails to guarantee a single canonical representation for every logical source URL**.  The missing empty‑path ↔ slash normalisation violates the core deduplication contract (Gate 7 F1, SUSTAINED) and opens the system to duplicate rows, privacy‑visibility inconsistencies, and ledger dead‑locks.  The defect is **high‑severity** because it directly impacts data integrity, storage costs, and the security guarantees around private‑visibility enforcement.

---

## Recommendations  

1. **Implement empty‑path ↔ slash normalisation** in `canonical_source_url` (see Fix 1).  
2. **Add explicit unit tests** covering the two variants (`https://example.com` and `https://example.com/`) and the ledger probe for both.  
3. **Consider tightening `ingested_source_urls`** to fall back to the canonical form when only one of the two variants exists (will be automatically satisfied after Fix 1).  
4. **Address the low‑risk hash‑length leakage** in `_log_ref` (Fix 5) to stay fully compliant with the “log‑only origin + short hash” policy.  
5. **Run the full test suite** with the added cases; confirm that no existing test expectations are broken.  

Once the above changes are merged, the Gate 7 contract will be restored: every document has a **single, deterministic dedup key** irrespective of trailing‑slash differences, and the ledger probe will correctly recognise already‑ingested URLs.
