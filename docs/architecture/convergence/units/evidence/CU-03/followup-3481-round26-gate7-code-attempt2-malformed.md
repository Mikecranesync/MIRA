## RECOMMENDATIONS
1. **Move evidence‑artifact exclusion before any diff logging.** Reorder the `main` function so that `drop_evidence_artifacts` (or at least a pre‑redaction that also strips evidence) runs **before** the `print` of the diff to `stderr`. This prevents raw artifact content from ever reaching CI logs.

2. **Rewrite `chunk_exists` to avoid `OR`.** Perform two separate indexed look‑ups (one for the raw URL, one for the canonical URL) or use a `UNION`/`IN` construct that can still leverage the `idx_ke_chunk_dedup` index. This restores O(log N) performance and mitigates DoS risk.

3. **Restore backward‑compatible signature for `shared_corpus_allowed`.** Either keep the original `bool`‑only return and expose the reason via a separate helper, or update all callers (including any external importers) to handle the new tuple. Add a deprecation shim that returns the bool for legacy callers.

4. **Validate `Retry‑After` header safely.** Parse the header with `int()` or use a safe fallback if conversion fails, e.g.:
   ```python
   header = getattr(r, "headers", {}).get("Retry-After")
   try:
       wait = float(header)
   except (TypeError, ValueError):
       wait = 15 * (retry + 1)
   ```

5. **Consider tightening evidence‑artifact rename rules.** Either reject any rename that moves an artifact out of the evidence directory, regardless of the new suffix, or add a secondary scan that redacts any suspicious content (e.g., secrets patterns) before inclusion in the prompt. At minimum, log a warning when an artifact is renamed to a code suffix.

6. **Add a CI test that captures the diff printed to `stderr`** and asserts that no path under `docs/architecture/convergence/units/evidence/` appears in the output. This will guard against regressions of the logging order.

Implementing these fixes will close the identified high‑severity data‑leak, improve database performance, maintain API stability, and harden the cascade against malformed provider responses.
