## FINDINGS
- **[severity: high] `url_has_userinfo` false‑positive for URLs containing “@” in the path, query or fragment** – In `tools/gate7_review.py` the function extracts the authority by taking everything after the scheme delimiter and then checks for the literal “@” in that entire remainder:

  ```diff
  ++    s = str(url).strip()
  ++    head, sep, rest = s.partition(":")
  ++    if not sep or not _URL_SCHEME_RE.fullmatch(head) or not rest.startswith("//"):
  ++        return False
  ++    authority = rest[2:]
  ++    return "@" in authority
  ```

  Because `authority` is not truncated at the first “/”, “?” or “#”, a perfectly valid URL such as `http://example.com/path@foo` (or `http://example.com?query@value`) will be treated as containing userinfo and therefore be refused. This causes legitimate URLs to be rejected, a denial‑of‑service defect not covered by the PR’s tests.

- **[severity: high] `url_has_userinfo` fails to detect percent‑encoded “@” (`%40`) in the authority, allowing credential‑bearing URLs to bypass the userinfo refusal** – The same snippet checks only for a literal “@” after the `//` delimiter:

  ```diff
  ++    authority = rest[2:]
  ++    return "@" in authority
  ```

  If an attacker supplies a URL like `http://user%40example.com@host/path` (where the credential part is percent‑encoded as `%40`), the function will not see the “@” and will incorrectly deem the URL safe, allowing it to pass the hop‑0 gate and be stored or logged. No test in the PR exercises this percent‑encoded case, leaving a high‑impact credential‑leak vulnerability.

## NOT REVIEWED
- Runtime interaction of the revised `url_has_userinfo` with downstream components that may rely on its return value (e.g., database writes, logging) beyond the unit tests provided.
- Performance impact of the modified authority extraction on very long URLs or URLs with complex Unicode characters, which is not exercised in the test suite.
- Potential side‑effects on existing migration scripts or external services that may have assumed the previous stricter parsing behavior.
