- **[severity: high] Strict section‑header parsing is case‑sensitive, allowing hidden high‑severity findings** —  
  `gate7_review.py` parses the mandatory sections of a fresh review (`## FINDINGS`, `## NOT REVIEWED`, `## VERDICT`) with a literal, case‑sensitive regular expression:  

  ```python
  FINDINGS_SECTION_RE = re.compile(r"^## FINDINGS$", re.MULTILINE)
  RULINGS_SECTION_RE  = re.compile(r"^## RULINGS$",  re.MULTILINE)
  VERDICT_SECTION_RE  = re.compile(r"^## VERDICT$",  re.MULTILINE)
  ```  

  Because the regexes match only upper‑case headings, a model that emits the same headings in any other case (e.g. `## findings`, `## Findings`, `## verdict`) is not recognised. In strict mode the parser then treats the section as absent, falls back to “no findings”, and the overall verdict is computed as **PASS** even if a high‑severity finding is present in the text. This bypass lets an adversarial reviewer hide a critical defect from the gate, violating the security contract that any high‑severity finding forces a `BLOCK`.
