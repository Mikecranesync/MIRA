- **[severity: high] Evidence‑artifact exclusion allows path‑traversal to hide files from review** —  
  The function `is_evidence_artifact` decides whether a file is an evidence artifact solely by checking `path.startswith(_EVIDENCE_DIR)` (`tools/gate7_review.py:176`). No path‑normalisation or resolution of “..” components is performed. Consequently a malicious file such as `docs/architecture/convergence/units/evidence/../outside/malicious.py` (or `malicious.log`) will satisfy the prefix test and be classified as an evidence artifact, causing `drop_evidence_artifacts` to drop the entire diff section for that file. This silently removes arbitrary files from the diff, bypassing all review, linting, secret‑scanning and tenant‑scoping checks.  
  Affected lines (excerpt):  
  ```diff
  +_EVIDENCE_DIR = "docs/architecture/convergence/units/evidence/"
  ...
  +def is_evidence_artifact(path: str) -> bool:
  +    if not path.startswith(_EVIDENCE_DIR):
  +        return False
  ```
  The lack of canonicalisation creates a high‑severity security boundary violation.

- **[severity: high] Adding “.log” to documentation suffixes widens the set of files treated as documentation and bypasses secret‑scanning** –  
  The `_DOC_SUFFIXES` tuple now includes `".log"` (`tools/gate7_review.py:262`). Many downstream security tools (secret‑scanners, credential‑leak detectors) skip files classified as documentation. By classifying *any* `.log` file—whether it is lane‑generated evidence or a developer‑added log—as documentation, the gate silently removes those files from security‑scanning. An attacker could place secrets in a `.log` file outside the evidence directory and have them ignored.  
  Affected lines (excerpt):  
  ```diff
  +_DOC_SUFFIXES = (".md", ".markdown", ".rst", ".txt", ".log")
  ```
