- **[severity: high] `_whole_dir_copy_dest` does not recognise multi‑line `COPY` directives** –  
  The packaging‑contract scanner is defined as:

  ```python
  def _whole_dir_copy_dest(dockerfile_text: str) -> str | None:
      """The destination of a whole-directory copy of ``mira-crawler`` …"""
      for line in dockerfile_text.splitlines():
          m = re.match(r"\s*COPY\s+(?:--\S+\s+)*(?:\./)?mira-crawler/?\s+(\S+)\s*$", line)
          if m:
              return m.group(1).rstrip("/")
          m = re.match(
              r'\s*COPY\s+(?:--\S+\s+)*\[\s*"(?:\./)?mira-crawler/?"\s*,\s*"([^"]+)"\s*\]\s*$', line
          )
          if m:
              return m.group(1).rstrip("/")
      return None
  ```

  The function scans **each line separately** and matches only single‑line `COPY` statements. Dockerfiles that use line‑continuation syntax, e.g.:

  ```dockerfile
  COPY \
      mira-crawler/ \
      /app/
  ```

  will return `None`, causing the contract test `test_every_crawler_image_copies_the_whole_directory_onto_the_import_path` to miss the omission. A Dockerfile could therefore omit the provenance manifest while still passing the test, leading to an unguarded ingest gate. This regression is not exercised by the current tests.

- **[severity: high] `_update_set_clauses` misses quoted column identifiers** –  
  The scanner used to detect `is_private` assignments is:

  ```python
  def _update_set_clauses(text: str) -> list[str]:
      """Everything between `UPDATE knowledge_entries` and its WHERE …"""
      return [
          m.group(1)
          for m in re.finditer(
              r"UPDATE\s+(?:\"?\w+\"?\s*\.\s*)?\"?knowledge_entries\"?(.*?)(?:\bWHERE\b|\Z)",
  ```
