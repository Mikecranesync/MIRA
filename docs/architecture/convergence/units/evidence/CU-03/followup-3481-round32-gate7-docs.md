## FINDINGS
- **[severity: high] Percent‑encoded unreserved characters are not normalized, enabling duplicate rows with inconsistent visibility** — `mira-crawler/ingest/store.py:12‑15`  
  ```diff
  _PCT_ESCAPE_RE = re.compile(r"%[0-9A-Fa-f]{2}")
  def _upper_escapes(component: str) -> str:
      # Upper‑case the hex digits of every valid %HH escape; nothing decoded; invalid % text
      # is left byte‑exact (RFC 3986 §[IP]) — nothing decoded, and invalid `%` text (`%7`, `%`,
      # `%zz`, `%7g`) is byte‑exact; every other byte preserved; idempotent.
      return _PCT_ESCAPE_RE.sub(lambda m: m.group(0).upper(), component)
  ```
  The canonicalisation routine only upper‑cases the hex digits of percent‑escapes and never
  decodes them. Consequently, two URLs that are semantically identical but differ in their
  percent‑encoding of unreserved characters (e.g. `http://example.com/~user` vs
  `http://example.com/%7Euser`) produce distinct canonical keys, are stored as separate rows,
  and are subject to independent visibility enforcement. A private row could be inserted with one
  encoding while a public row with the alternative encoding bypasses the private‑only check,
  resulting in unintended exposure of private content. No test in this PR exercises this
  equivalence, so the regression is undetected by existing CI.

- **[severity: medium] Hostnames are lower‑cased but not IDNA‑normalized, allowing duplicate rows for Unicode domains** — `mira-crawler/ingest/store.py:31‑33`  
  ```diff
  scheme = _up(url).scheme.lower()
  host = (urlparse(str(url)).hostname or "").lower()
  ```
  The implementation lowers the host string but never applies IDNA (punycode) conversion or Unicode
  normalization (NFC/NFD). URLs that differ only in Unicode normalization of the domain label
  (e.g. `http://xn--exmple-cua.com` vs `http://exämple.com`) will generate different canonical keys
  and be stored as separate rows. This can lead to duplicate storage with divergent `is_private`
  settings, potentially exposing private data. The test suite does not cover Unicode domain
  normalization, so this edge case remains unchecked.
