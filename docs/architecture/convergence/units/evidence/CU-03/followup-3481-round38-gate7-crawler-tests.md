## FINDINGS
- **[severity: high] canonical_source_url retains fragment identifiers, breaking deduplication** —  
  The `store.canonical_source_url` function leaves the URL fragment (`#…`) unchanged, causing semantically identical resources that differ only by fragment to be stored as separate rows. This defeats the deduplication guarantee, inflates storage, and can leak usage patterns (e.g., which fragment variants were requested). The test suite explicitly asserts that fragments are preserved, confirming the lack of normalization:  

  ```python
  assert store.canonical_source_url(
      "HTTPS://EXAMPLE.COM/Path/File.PDF?Q=A&b=B#Frag"
  ) == "https://example.com/Path/File.PDF?Q=A&b=B#Frag"
  ```

  Because fragments are client‑side only and do not affect the fetched document, they should be stripped during canonicalisation. The current behaviour creates duplicate rows for the same source URL with different fragments, violating the intended “one row per logical document” invariant and opening the door to data bloat and privacy leakage across tenants.

- **[severity: high] canonical_source_url does not resolve dot‑segments (`.` and `..`) in the path** —  
  The function performs only scheme/host lower‑casing, default‑port removal, and percent‑escape case‑folding, but it never normalises the path component. Consequently, URLs such as `https://example.com/a/../b` and `https://example.com/b` are treated as distinct keys, allowing duplicate ingestion of the same resource. The test suite asserts that the path is left untouched for a normal URL, which implicitly demonstrates that dot‑segment removal is not performed:  

  ```python
  assert store.canonical_source_url(
      "HTTPS://EXAMPLE.COM/Path/File.PDF?Q=A&b=B#Frag"
  ) == "https://example.com/Path/File.PDF?Q=A&b=B#Frag"
  ```

  By not normalising path dot‑segments, the system fails to collapse equivalent URLs, undermining deduplication and opening a vector for storage‑based denial‑of‑service (an attacker can flood the system with syntactically different but semantically identical URLs). This defect is not covered by the existing contract tests.
