## Raw review

**⚠️ HIGH‑SEVERITY DEFECT – CASE‑SENSITIVITY IN EVIDENCE‑ARTIFACT DETECTION**  

**File:** `tools/gate7_review.py`  
**Location:** `is_evidence_artifact()` (lines ~710‑735)  

---

### 1. What the code does today
```python
_EVIDENCE_DIR = "docs/architecture/convergence/units/evidence/"

def is_evidence_artifact(path: str) -> bool:
    """Return True for a preserved review artifact (raw reviewer output,
    adjudication, stderr logs) that lives under the evidence directory."""
    if not path.startswith(_EVIDENCE_DIR):
        return False
    name = path.rsplit("/", 1)[-1].lower()
    if not name.endswith(_DOC_SUFFIXES):
        return False
    return name != "readme.md" and "rebuttal" not in name
```

* The function decides whether a file **must be excluded from the reviewed diff** (and therefore listed in the receipts) purely by checking if its **path string starts with the literal lower‑case prefix** stored in `_EVIDENCE_DIR`.  
* The check is **case‑sensitive** (`str.startswith`), while the rest of the function normalises only the *filename* (`name.lower()`).  

### 2. Why this is a problem  

| Attack scenario | What happens |
|-----------------|--------------|
| **a. Mixed‑case path** – an attacker creates `Docs/Architecture/Convergence/Units/Evidence/round‑9‑review.md` (capital “D”, “A”, “C”, “U”, “E”). | `path.startswith(_EVIDENCE_DIR)` returns **False** because the prefix differs in case. The file is **not recognised as an evidence artifact**. |
| **b. Leading `./`** – a PR that includes `./docs/architecture/convergence/units/evidence/round‑9‑review.md`. | The leading `./` prevents the literal prefix match; the artifact is again **kept**. |
| **c. Windows case‑insensitivity** – on Windows the repository may be checked out with a different case‑style (e.g., `DOCS/...`). The same mismatch occurs. | Same as (a). |

When the file is *not* identified as an evidence artifact:

1. **`drop_evidence_artifacts()` does not strip it** – the diff line `diff --git a/... b/...` (and any surrounding diff hunks) remain in the *reviewed* diff that is sent to the LLM provider.  
2. **`pr_kind(reviewed_paths(diff))` may mis‑classify the PR** (e.g. “mixed” instead of “code”) because the file has a `.md`/`.log` suffix. This changes the brief’s “decision‑point reminder” and may hide the “historical EVIDENCE” notice that the operator expects.  
3. **Sensitive data leakage** – raw reviewer output, adjudications or `stderr` logs frequently contain API keys, passwords, IP/MAC addresses, or other secrets. The redaction step runs *before* artifact dropping, but it only knows about obvious patterns (IP/MAC/`[SECRET]`) and does **not** scrub arbitrary secrets that may appear inside evidence artifacts. Consequently, the un‑redacted secret text is sent to the external LLM provider and also written to the receipts block, violating the *“store logging may leak credentials”* and *“evidence artifacts excluded from review”* contracts.

The defect is **not covered by the existing test‑suite**:

* `tests/test_gate7_review.py::test_preserved_evidence_artifacts_are_dropped…` uses **lower‑case** paths only.  
* No test supplies a mixed‑case or `./`‑prefixed evidence path.  
* No test verifies that `is_evidence_artifact` is case‑insensitive.

Therefore the issue is a **structural blind‑spot** that a malicious author could exploit to sneak secret‑containing artifacts into a review that the Gate 7 pipeline will treat as normal code, potentially leaking them to the LLM provider and to the run receipts.

### 4. Suggested Fix (minimal change)

1. **Normalize the path before the prefix check** – treat the prefix case‑insensitively and tolerate a leading `./`:

```python
_EVIDENCE_DIR = "docs/architecture/convergence/units/evidence/"

def _norm_path(p: str) -> str:
    """Return a lower‑cased, dot‑stripped version of a diff path for internal checks."""
    # Strip a leading "./" that `git diff` may emit on some platforms.
    if p.startswith("./"):
        p = p[2:]
    return p.lower()

def is_evidence_artifact(path: str) -> bool:
    norm = _norm_path(path)
    # Use a lower‑cased prefix for case‑insensitive matching.
    if not norm.startswith(_EVIDENCE_DIR):
        return False
    name = norm.rsplit("/", 1)[-1]
    if not name.endswith(_DOC_SUFFIXES):
        return False
    return name != "readme.md" and "rebuttal" not in name
```

2. **Update `drop_evidence_artifacts`** to use the same normalisation for `source` and `target` when calling `is_evidence_artifact`. This guarantees that renames and deletions are also correctly detected irrespective of case.

3. **Add tests** to cover the edge‑cases:

```python
def test_evidence_artifact_detection_is_case_insensitive():
    mixed = "Docs/Architecture/Convergence/Units/Evidence/round-9-review.md"
    dot = "./docs/architecture/convergence/units/evidence/round-9-review.md"
    assert is_evidence_artifact(mixed) is True
    assert is_evidence_artifact(dot) is True
```

4. **Run the new tests under the existing CI matrix** (they will execute in the `test_gate7_review.py` suite).

### 6. Conclusion

The current implementation of `is_evidence_artifact()` (and the downstream `drop_evidence_artifacts()`) **fails to treat the evidence directory path case‑insensitively**. This opens a concrete path for a malicious PR author to hide raw review artefacts (which may contain secrets) under a mixed‑case or `./`‑prefixed path, causing them to be included in the diff sent to the LLM provider and omitted from the receipts block.  

Given the gate’s mandate to *prevent secret leakage* and *preserve tenant isolation*, this is a **high‑severity security regression** that must be fixed before the PR can be safely merged.
