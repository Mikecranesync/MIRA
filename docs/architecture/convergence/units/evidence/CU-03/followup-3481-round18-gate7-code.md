- **[severity: high] `_urls_in` incorrectly treats docstrings as origin URLs** — the helper that extracts hard‑coded origins (`_urls_in` in `mira-crawler/ingest/origins.py`) walks every `ast.Constant` node that contains a string and only checks that the string lower‑cases to `"http://"` or `"https://"`:

```diff
-        and isinstance(n, ast.Constant)
-        and isinstance(n.value, str)
-        and n.value.startswith(("http://", "https://"))
+        # Scheme match is case‑insensitive (Gate 7 round‑12 group A on #3268):
+        # a constant written `HTTPS://...` is still a configured origin, and a
+        # manifest discovery that missed it would leave the policy consistency
+        # test vacuous for that origin.
+        and isinstance(n, ast.Constant)
+        and isinstance(n.value, str)
+        and n.value.lower().startswith(("http://", "https://"))
```

`ast.Constant` also includes module‑level docstrings and function‑level docstrings, which are not real origin declarations. By treating these docstrings as origins, the system will demand policy entries for URLs that never appear in production traffic, causing **false‑positive policy violations** and potentially **blocking legitimate PRs**. Moreover, a malicious contributor could embed a sensitive URL in a docstring to force an unnecessary policy failure or to hide the URL from security scans (the URL will be lower‑cased and classified as an origin). This regression defeats the intended guarantee that only *actual* origin constants are scanned and is a security‑relevant defect.

- **[severity: medium] Scope‑notice can explode token count on large PR slices** — the newly added `_scope_notice` unconditionally enumerates *every* file excluded by a `--paths` slice:

```python
def _scope_notice(excluded: Optional[list[str]]) -> str:
    if not excluded:
        return ""
    return (
        f"\n⚠️ SCOPE NOTICE — you are reading a --paths SLICE of this PR, not the PR.\n"
        f"{len(excluded)} changed file(s) are outside your slice and exist in the PR:\n"
        + "\n".join(f"  - {p}" for p in excluded)
        + '\nTherefore: "the diff does not contain X" / "the only file changed is Y"\n'
        "is NOT a finding here. A claim that this PR changes one of the files above is settled\n"
        "by that file's own group, not by its absence from yours. Do not report the absence.\n"
    )
```

When a PR modifies a large number of files (e.g., > 150) outside the scoped paths—as is the case in the current diff (160 files)—the generated notice can add tens of kilobytes of text to the prompt. The prompt already contains the diff (truncated to `MAX_DIFF_CHARS`) and the decision‑point reminder, pushing the total token count well beyond the model’s `max_tokens` (24 k/32 k). This can cause the LLM request to be rejected, resulting in a **fallback to a substitute panel** and loss of the review. The gate’s automation must guard against prompt overflow, e.g. by truncating or summarising the excluded‑file list.
