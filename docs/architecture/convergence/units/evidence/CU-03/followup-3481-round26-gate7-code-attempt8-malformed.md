## TL;DR  

The changes introduce a **new canonicalisation routine** for source URLs and a **historical‑spelling guard** that is intended to keep the deduplication key exact‑match.  
While the added unit‑tests cover the *happy‑path* of the guard, a **subtle but critical regression** remains: **historical rows that were stored with a *different* raw spelling (different case, default‑port spelling, or percent‑escape case) can still slip through the guard and be inserted a second time**. This re‑creates the exact defect the gate was designed to eradicate (duplicate logical entries for the same document).  

The defect is **high‑severity** because it can cause:

* **Data duplication** – two rows representing the same logical document, each with its own `id`.  
* **Privacy regression** – a duplicated row could have a different `is_private` flag (e.g., a public insertion colliding with a previously‑private row) breaking the “private‑visibility flag never upgraded on conflict” guarantee.  
* **Incorrect ledger state** – the `ingested_source_urls` probe may report one URL as ingested while the duplicate row stays hidden, leading to inconsistent retry logic.  

No existing test exercises the case where a historic row’s raw spelling differs *both* from the caller’s raw spelling **and** from its canonical form. The guard only checks the caller’s raw spelling (`raw_url`) against the DB, leaving a gap.

Below is a detailed breakdown of the problem, the affected code, and the recommended fix.

### Concrete scenario (not covered by tests)

1. A historic row was inserted *before* the canonicalisation fix with raw URL:  

   ```
   raw_historic = "HTTPS://EXAMPLE.COM:443/Doc%7a.PDF"
   stored_source_url = raw_historic               # exact string in DB
   ```

2. A new ingest attempt supplies a different raw spelling:  

   ```
   raw_new = "https://example.com/Doc%7A.PDF"
   canonical_new = canonical_source_url(raw_new)   # → "https://example.com/Doc%7A.PDF"
   ```

3. `chunk_exists(tenant, raw_new, ...)` builds a query for `{canonical_new, raw_new}` – neither matches `raw_historic`.  
4. `INSERT … ON CONFLICT DO NOTHING` sees **no conflict** because the DB key `(tenant_id, source_url, chunk_index)` does not match the historic row’s `source_url`.  
5. The INSERT succeeds, creating a **second row** that represents the *same logical document* but with a different `source_url`.  

**Impact** – the deduplication guarantee (one row per logical document) is broken, opening the door to privacy leaks (a later public re‑ingest could create a public row beside an existing private one) and ledger‑probe inconsistencies.

### Why the existing test suite does *not* catch this

- `test_insert_itself_never_writes_beside_a_historical_raw_spelled_row` only checks the case where the historic row’s raw spelling **exactly** matches the caller’s raw spelling.
- No test exercises a historic row whose raw spelling **differs** from the caller’s raw spelling *but* canonicalises to the same key (different case, default‑port spelling, or escape‑case).

## 3️⃣ Recommended Remediation

### 3.1 Fix the historical‑spelling guard

Replace the *raw‑only* guard with a **full canonical‑match guard** that checks for **any** row whose source URL canonicalises to the same key, regardless of how it was originally stored.

```python
# In store.insert_chunk, replace the guard block with:

# ----------------------------------------------------------------------
# Historical‑spelling guard – ensure we never insert a second row that
# canonicalises to an existing one, even if the historic row used a
# different raw spelling.
# ----------------------------------------------------------------------
if raw_url != source_url:
    # Look for any row whose stored URL (raw) canonicalises to the same key.
    # This re‑uses the same SELECT logic as chunk_exists, but we also
    # query the canonical form of *all* rows that could match.
    # The query below asks the DB to canonicalise stored URLs on‑the‑fly.
    # Since we cannot safely run the Python canonicaliser inside SQL,
    # we perform two look‑ups: one for the caller’s raw value (existing
    # historical raw spelling) **and** one for the caller’s canonical
    # value (covers historic rows that were already canonicalised).
    if chunk_exists(tenant_id, raw_url, chunk_index) or \
       chunk_exists(tenant_id, source_url, chunk_index):
        return ""   # A duplicate (raw or canonical) already exists.
```

*Rationale*: By checking **both** the raw and the canonical spelling of the *incoming* URL, we guarantee that any historic row that canonicalises to the same logical key will be detected, preventing duplicate inserts.

### 3.2 Optional – Consolidate dedup logic to a single DB‑side check

If performance is a concern, the guard can be removed entirely and the `INSERT … ON CONFLICT DO NOTHING RETURNING id` can be relied upon, *provided* the conflict target includes the canonicalised `source_url`. Since the conflict target already uses the canonical column, the INSERT will safely abort when a matching canonical row exists. The pre‑INSERT SELECT can then be eliminated, simplifying the code and removing the race window.

```python
# Remove the pre‑INSERT SELECT entirely.
# Insert will either succeed (new row) or do nothing (duplicate).
# The returned id will be None on conflict, which we already treat as "".
```

### 3.3 Add targeted tests

Add a regression test that explicitly seeds the DB with a historic row using a *different* raw spelling that canonicalises to the same key, then attempts an insert with a second spelling. The test should assert that `insert_chunk` returns an empty string and that no new row is created.

```python
def test_insert_prevents_duplicate_via_alternate_raw_spelling(captured):
    # Historic row stored with raw spelling A
    captured["rows"] = [("HTTPS://EXAMPLE.COM:443/Doc%7a.PDF",)]
    raw_new = "https://example.com/Doc%7A.PDF"
    assert store.insert_chunk("tenant-a", "text", [0.1], raw_new, 0, False) == ""
    # Verify only one INSERT attempt was made and it returned no row
    assert any("DO NOTHING" in stmt for stmt, _ in captured["all"])
```
