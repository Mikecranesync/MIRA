## FINDINGS
- **[severity: high] Race condition in `insert_chunk` duplicate detection** – The implementation first checks for an existing chunk with a separate `SELECT` (`chunk_exists`) and then performs an `INSERT … ON CONFLICT DO NOTHING`. The existence check and the insertion are not performed atomically. Two concurrent ingestion tasks can both see that no matching row exists (because the `SELECT` does not lock the table), then both attempt to insert. If the two calls use different spellings of the same URL (canonical vs raw) they will each bind a different value to `source_url`, and the `OR` clause (`source_url = :url OR source_url = :raw`) will not prevent both inserts from succeeding. This can produce duplicate rows for the same logical source URL.  

  If the concurrent callers differ in the `is_private` flag (e.g., one inserts a private chunk, the other a public chunk), the race can result in a private chunk being stored alongside a public duplicate, violating the tenant‑scoping and privacy guarantees.
