## FINDINGS
- **[severity: high] `_urls_in` does not inspect URLs inside f‑strings (ast.JoinedStr), allowing credential‑bearing URLs to bypass user‑info and query‑parameter checks**  
  `mira-crawler/ingest/origins.py`  
  ```python
  for n in ast.walk(tree):
      if isinstance(n, ast.Constant) and isinstance(n.value, str) \
          and n.value.lower().startswith(("http://", "https://")):
          urls.add(n.value.strip())
  ```  
  The implementation only walks `ast.Constant` nodes. URLs built with f‑strings (e.g. `f"https://{user}:{pwd}@host/path"`) are represented as `ast.JoinedStr` nodes and are never added to `urls`. Consequently, the provenance policy’s `url_has_userinfo` and the credential‑family query‑parameter checks are never applied to such dynamically‑constructed URLs. An attacker could embed a credential‑bearing URL in an f‑string, have it stored verbatim, and bypass all existing safeguards. This defect is not covered by the current test suite (which only exercises constant literals) and represents a real security regression.

## NOT REVIEWED
- Runtime behaviour of the crawler when URLs are assembled from external input (e.g., via string concatenation, `format`, or template rendering) is not exercised by the static AST discovery.  
- Potential interactions with third‑party libraries that generate URLs at runtime (e.g., `urllib.parse.urlunparse`) are not verified.  
- The impact of this gap on downstream services that consume stored URLs has not been measured.
