## FINDINGS
- **[severity: high] Evidence‑artifact detection is case‑sensitive, permitting secret files to bypass exclusion and be sent to the LLM**  
  - **What breaks**: The helper `is_evidence_artifact` in `gate7_review.py` determines whether a file is an evidence artifact by performing a simple case‑sensitive prefix check:  

    ```python
    EVIDENCE_ROOT = "docs/architecture/convergence/units/evidence/"
    def is_evidence_artifact(path: str) -> bool:
        return path.startswith(EVIDENCE_ROOT)
    ```  

    Because the comparison is case‑sensitive, a file whose path differs only in letter case (e.g., `Docs/Architecture/Convergence/Units/Evidence/CU-03/secret.log`) is *not* recognised as an evidence artifact. Consequently, `drop_evidence_artifacts` retains the file, and the raw diff – including any unredacted secrets inside the file – is sent to the language model. This violates the security boundary that evidence artifacts must never be exposed to the model.  

  - **Concrete evidence (diff line)**: Adding the following file to a PR would trigger the defect:  

    ```
    diff --git a/Docs/Architecture/Convergence/Units/Evidence/CU-03/secret.log b/Docs/Architecture/Convergence/Units/Evidence/CU-03/secret.log
    new file mode 100644
    --- /dev/null
    +++ b/Docs/Architecture/Convergence/Units/Evidence/CU-03/secret.log
    @@ -0,0 +1 @@
    +API_KEY=SUPER_SECRET_123
    ```  

    The path does not match the lower‑case `EVIDENCE_ROOT`, so `is_evidence_artifact` returns `False`. `drop_evidence_artifacts` keeps the file, `receipts_block` does not list it as excluded, and the secret line `API_KEY=SUPER_SECRET_123` is transmitted to the LLM unredacted.  

  - **Location in code**: `gate7_review.py`, function `is_evidence_artifact` (prefix check) and its consumer `drop_evidence_artifacts`.  

  - **Why the test suite missed it**: `tests/test_gate7_review.py` only asserts positive detection for the exact lower‑case path and negative detection for a handful of unrelated filenames. It never exercises case‑variations of the evidence‑artifact prefix, leaving this case‑sensitivity bug uncovered.  

  - **Impact**: Leakage of potentially sensitive logs, credentials, or other private data to the LLM, violating tenant isolation and the non‑secret‑boundary contract. An attacker can deliberately craft a PR that includes a secret file with a mixed‑case path to exfiltrate data.

## NOT REVIEWED
We could not execute the full ingestion pipeline to confirm that downstream components (e.g., any later path‑normalisation step) do not already normalise case before the `is_evidence_artifact` check. Additional testing with a PR that adds a mixed‑case evidence‑artifact path would verify whether the secret is indeed sent to the LLM. Moreover, we have not examined whether the redaction step (`redact`) would strip the secret from the file content; however, redaction is applied *after* the diff is built and the file is already included in the prompt, so any secret present in the diff would already be exposed. This remains a high‑severity security regression.
