- **[severity: high] `canonical_source_url` does not canonicalise default ports** — The function lower‑cases the scheme and host but retains explicit port numbers, even when they are the default for the scheme. Consequently  
  ```python
  canonical_source_url("https://example.com/file.pdf")   # → "https://example.com/file.pdf"
  canonical_source_url("https://example.com:443/file.pdf") # → "https://example.com:443/file.pdf"
  ```  
  are treated as **different** keys. The unique index `idx_ke_chunk_dedup` (tenant_id, source_url, chunk_index) therefore permits two rows that refer to the *same* logical document.  
  *Impact*: a private ingest of `https://example.com:443/file.pdf` could coexist with a public ingest of the same document without conflict, leaking private content through the public row. This is a data‑corruption / privacy breach.

- **[severity: high] Percent‑encoding case is not normalised** — `canonical_source_url` preserves the exact byte sequence of the path, query, and fragment, including the case of percent‑encoded octets. RFC 3986 treats `%AB` and `%ab` as equivalent, but the function does not normalise them, leading to duplicate rows for URLs that only differ in percent‑encoding case.
