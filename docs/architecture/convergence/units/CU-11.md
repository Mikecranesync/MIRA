## Target architecture

An **invocable, evidence-producing** Gate 7 lane that any unit can run and any unit
record can cite:

- `tools/gate7_review.py` — disprove-brief review of a PR/branch diff on the free-tier
  **Groq → Cerebras → Together** cascade (owner decision in merged PR #3261: **no

  `TOGETHERAI_API_KEY` is live in `unseen-generalization-lane.yml`).
- `/gate7-review` (`.claude/commands/gate7-review.md`) — the procedure: finalize diff →
  cascade lane → (xhigh) fresh-context agent reviewers in isolated worktrees → paste the
  evidence block into the unit record → BLOCK is stop-the-line → re-run per round.
- §Gate 7 doctrine text amended to stop naming a rejected provider and to state the
  honesty requirement (below).

## Canonical implementation

- **`tools/gate7_review.py`** (new): gathers the diff (`gh pr diff N` or
  `git diff BASE...HEAD`), builds a disprove brief (the §Gate 7 refutation axes verbatim +
  optional unit record + capped diff), calls the cascade with `httpx`, parses an explicit
  `Verdict: PASS|BLOCK`, and emits a structured evidence block naming every provider that
  ran. Effort semantics: `high` = first available provider decides; `xhigh` = **every**
  available provider reviews (min 2) and all must PASS. Exit codes: 0 PASS / 1 BLOCK /
  2 indeterminate / 3 lane unavailable. **Fail-loud by design** — unlike the advisory
  `code-review.yml` comment bot, provider failure is never a pass.
- **`.claude/commands/gate7-review.md`** (new): the invocable step + the evidence shape.
- **Doctrine amendments** (4 sites): §Gate 7 default (lane + honesty note), §Gate 7
  xhigh semantics, §9 Adversarial Reviewer, §15 pilot chain line, §20 reviewer line.

**Honesty requirement (stated, not implied away):** without a dedicated second frontier
vendor, "independent" means **fresh context** (stateless call; the reviewer sees only the
brief + diff), **an isolated worktree** when the reviewer is an agent, and **a brief to
disprove** — *not vendor independence*. The evidence block prints this basis so a unit
record cannot imply a cross-vendor check that did not happen.

## Contracts/invariants

- The lane never soft-skips: every non-PASS state has a distinct non-zero exit code.
- The evidence block always names the providers that actually ran and the independence
  basis.
- Cascade order and providers are PRD §4 (Groq → Cerebras → Together); no Anthropic, no
  OpenAI-the-vendor (gpt-oss-120b is an open-weights model served by the free-tier
  providers, not an OpenAI API dependency).
- Known limitation (recorded, accepted): `DIFF_CHAR_CAP = 48_000` chars (raised from 24k
  after round 1, where CU-11's own diff was cut mid-file and reviewers hallucinated
  defects at the cut point) — larger diffs are truncated with a loud warning and the brief
  tells the reviewer to flag load-bearing cuts. Free-tier TPM is the binding constraint;
  big units should review per-commit or per-file-group.
- Known limitation (recorded, accepted — substitute-panel finding): **prompt injection.**
  The diff is attacker-influenced text inside the reviewer prompt; the brief marks it as
  untrusted data and makes manipulation attempts a blocking finding, but an LLM
  instruction is not a security boundary. **Gate 9 (human GO) is the backstop — a lane
  PASS alone never authorizes a merge.**
- Known limitation (recorded, accepted): argparse usage errors exit 2, colliding with the
  indeterminate-verdict code by number alone (unambiguous from the usage text on stderr).

### Lane dogfood — rounds 1–3 (2026-08-16, `--effort xhigh`, all 3 providers each round)

Every round executed end-to-end (evidence blocks archived by the session; verdict lines and
provider attempts reproduced in the PR body). All three rounds returned **BLOCK**. Triage:

**Round 1 findings that were REAL (fixed in-branch):**
- Uncaught exceptions in input gathering exited 1 — indistinguishable from BLOCK. Fixed:
  infra failures now map to exit 3 (`fix` commit).
- `DIFF_CHAR_CAP=24k` truncated CU-11's own 27.5k diff mid-file, and reviewers hallucinated
  a "syntax error" at the exact cut point. Fixed: cap 48k + loud truncation warning.

**Round 2 findings that were REAL (fixed in-branch):**
- Provider key could theoretically reach logs via exception text. Fixed: key redacted from
  all exception paths (defensive — httpx error strings do not actually carry headers).
- No offline tests for the decision logic. Fixed: `tests/test_gate7_review.py` (verdict
  parsing incl. mid-line-quote and conflicting-verdict cases, brief construction, exit-code
  map), wired into `ci.yml` architecture-check so it cannot be an unwired false-green.

**Recurring findings REFUTED with evidence (recorded so CU-03 doesn't re-litigate them):**
- "Missing key ⇒ crash / None Bearer" — false: providers are filtered by key presence and
  each call is wrapped with fallthrough.
- "INDETERMINATE never mapped to exit 2" — false: the map exists and is test-locked.
- "`openai/gpt-oss-120b` contradicts no-OpenAI" — false: open-weights model namespace on
  the free-tier providers, not an OpenAI API dependency (stated in the brief's accepted
  context; the reviewers repeat it anyway).
- "Stale Codex/GPT-5.6 Sol references remain in the doctrine" — false: `grep -n` shows the
  only remaining mentions are the amendment's own historical quote and §20's generic
  agent-naming line (deliberately kept).
- "Tests could make real network calls" — false: tests never invoke `main()`/`call_provider`.
- "httpx is an undeclared dependency" — httpx is the repo-standard HTTP client; the CI step
  installs it explicitly.

**Recurring findings RECORDED-ACCEPTED (platform policy — Gate 9 owns the override):**
- The lane sends diffs/unit records to the free-tier providers. Same trust boundary as the
  existing `code-review.yml` advisory pipeline (which posts PR diffs to the same providers);
  commits are gitleaks-scanned pre-commit. Accepted by design.
- Cascade logic exists in both this lane and `code-review.yml`. Deliberate: different
  failure semantics (advisory soft-skip vs fail-loud gate); unifying is a future refactor,
  out of CU-11's surgical scope. (`code-review.yml`'s third slot is also still Gemini,
  pre-dating the Together switch — noted, untouched.)
- `--out` overwrites; no retries/metrics. Simplicity-first: rounds use distinct filenames;
  the cascade fallthrough is the retry.

**Honest characterization (the key observation for future units):** at xhigh with an
aggressive disprove brief, the gpt-oss cascade **over-blocks** — it reports accepted
platform policy as blocking findings even when the brief explicitly pre-empts them. This is
the reviewer-quality ceiling of the no-OpenAI decision, stated rather than hidden. The
discipline is: **triage every finding (fix / refute-with-evidence / record-accept), never
weaken the gate to force a PASS.** A raw BLOCK verdict is the start of triage, not the end;
Gate 9's human GO is the override authority for policy-class findings. If over-blocking
persists across CU-03, calibrate the brief further or move the verdict to
"blocking-findings-surviving-triage" — but that is a future, recorded change.

### Substitute fresh-context panel (the authoritative review for this unit)

Three independent fresh-context reviewer agents, distinct disprove axes, read-only,
reviewing the branch worktree (2026-08-16). Verdicts: **lane-correctness BLOCK ·
record-honesty BLOCK · platform-compliance PASS.** Every finding was empirically
reproduced by the reviewer before being reported. Dispositions — all blocking/important
findings **fixed in-branch** in the round-2 hardening commit:

- **[blocking, reproduced] xhigh silently degraded**: a provider erroring after the key
  check (e.g. a 429) dropped out of "all must pass", so an xhigh run could exit 0 on a
  single surviving reviewer — the exact rate-limit failure mode this record's observation
  window predicts. **Fixed:** at xhigh, `len(reviews) < len(available)` → exit 3
  (degraded lane is unavailable, not a verdict).
- **[important, reproduced] verdict-parse false-greens**: the model echoing the prompt's
  own format line ("Verdict: PASS or Verdict: BLOCK …") parsed as PASS even alongside a
  `[blocking]` finding; a genuine BLOCK plus a quoted PASS demoted to INDETERMINATE.
  **Fixed:** full-line-only verdict matching; a line-anchored `- [blocking]` finding
  forces BLOCK over any stated verdict; conflicting verdicts resolve to BLOCK; and
  cross-provider aggregation now has BLOCK dominate INDETERMINATE. All cases test-locked.
- **[important, reproduced] exit-code collisions**: a failed `--out` write after a
  genuine verdict escaped as an uncaught traceback (interpreter exit 1 = BLOCK's code).
  **Fixed:** wrapped → exit 3. The argparse-usage exit-2 collision is documented as a
  known limitation (above) rather than remapped.
- **[important] prompt injection unacknowledged**: **fixed** by the untrusted-data brief
  instruction + the recorded-accepted limitation above naming Gate 9 as the backstop.
- **[important] record honesty — stale claims**: the record said `DIFF_CHAR_CAP=24_000`
  after the code moved to 48k, said "no pytest contract added" after tests shipped, and
  pointed at evidence "below" that was still a placeholder. **Fixed:** this record was
  corrected (see the history note in Gate 3) — the panel catching the record drifting
  from its own diff, on the unit whose theme is record honesty, is the process working.
- **[minor] unit-record prompt truncation was silent** (unlike the diff's): **fixed**
  (warning + `[UNIT RECORD TRUNCATED]` marker). **[minor] gpt-oss reasoning headroom**:
  **fixed** (`MAX_TOKENS` 4096→8192; empty completions already fail loud). **[minor]
  unstable review target** (panel observed mid-round WIP in the worktree): accepted —
  the rounds are sequential by design; the final lane round runs on the final committed
  diff. **[minor] doctrine line 704 still names Codex**: deliberately kept — it names
  Codex as a generic implementation agent (same phrasing as other repo rules), not the
  rejected reviewer role; all five reviewer-role sites are amended (panel verified by
  grep).
