## What this slice proves

The opt-in v2 read pins one job sequence, snapshot and explicit candidate
revision/body hash. One bounded projection feeds the existing guide and selected
notebook question. Historical job identity, recorded work and correction lineage
remain separate from dated graph/observation/document/CMMS reads. A changed or
missing asset binding refuses a new pinned question; a completed identical turn
replays without consulting current stores. Source-only selection never becomes
the latest candidate. No source, graph, CMMS, protocol or schema write is added.

The full v2 record is retained; the added context is bounded to24KiB with explicit
coverage/omissions. It does not become approved OEM evidence or bypass existing
chat admission. The selected job augments an already admitted/general answer;
a standalone job-only answer journey remains unproven.

## Reproduce the portable fictional component proof

From the repository root with existing Hub dependencies and Playwright Chromium:

```sh
node docs/proofs/asset-memory-first-slice/render.mjs /tmp/mira-asset-memory-proof /tmp/mira-asset-memory-proof/guide.pdf
node docs/proofs/asset-memory-first-slice/browser-check.mjs /tmp/mira-asset-memory-proof
cd mira-hub
npm test -- --cache=false
npx tsc --noEmit --incremental false
npm run sitemap:check
```

The renderer stubs server I/O, uses the actual pure projection/Guide, and creates
a completely fictional fixture. The browser proof mocks fetch and exercises late
job responses, pending execution invalidation, selection refresh, and retry with
the original frozen request body/target. No customer data, credential, paid
provider, shared database or industrial connection is needed. These proof
scripts are outside product compilation. The committed PDF and screenshots are
the inspected output; render metadata can vary between runs.

## Remaining acceptance gaps

- Existing PUMP-01/Atlas1652 control has unknown historical UNS, unlinked external
  asset, no component/manual source associations, and no full clocked event
  export. The orders were OPEN in the retained evidence. No missing relation was
  invented from a name, seed UUID or description match.
- One fresh, authorized, authenticated technician journey must establish those
  links and compare original source pages, saved record, served answer and guide.
  The current private answer evidence manifest preserves what was served but
  does not add public Asset Memory citation chips or automatic guide discovery.
- Later reusable acceptance, full historical graph/document version manifests,
  automatic step assembly and device restart recovery remain separate work.
- Observation-owner #5104 changes the lower-level read return shape; that later
  merge must adapt this consumer. Its files are deliberately untouched here.
- Shared staging/production migrations, merge and deployment require their
  existing gates and authority. No authorization or successful outcome is
  inferred from local tests or this document.
