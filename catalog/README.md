# FactoryLM / MIRA Repository Catalog

A **durable, evidence-backed, machine-readable** catalog of every repository in the
`Mikecranesync` org and the important systems inside the active ones. Built by the
Repository Archaeology run (2026-07-14). Every `confirmed` fact carries provenance
(repository / file / commit / detection_method); see `schema/fact.schema.json`.

> **This is not a shallow file dump or a speculative architecture document.** Claims are
> tied to code, config, git, tests, or deploy files. Where a claim is derived (e.g. from a
> gh description) it is marked `strong-inference`; open questions live in `unknowns.md`.

## Layout

| Path | What |
|---|---|
| `organization.yaml` | **Phase 1.** All 98 org repos, classified. GENERATED by `build_organization.py`. |
| `repositories/<repo>.yaml` | Per-repo detail for the active repos (branch, langs, CI, deploy, modules, relationships). |
| `services.yaml` | **Phase 2.** Applications / services / workers / agents — component records. |
| `apis.yaml` | HTTP routes / MCP tools / CLIs entry points. |
| `databases.yaml` | Databases, schemas, key tables, tenancy model. |
| `schemas.yaml` | Migration lineages + notable schema facts. |
| `workers-and-crons.yaml` | Celery/async workers, scheduled jobs, GitHub cron workflows, launchd. |
| `integrations.yaml` | External services (LLM providers, Stripe, Doppler, Neon, Telegram, Slack, Ignition…). |
| `deployments.yaml` | Compose files, environments, deploy workflows, VPS targets. |
| `environment-variables.yaml` | Notable env vars + where they're read. |
| `feature-flags.yaml` | Feature/enforcement flags. |
| `dependencies/` | **Phase 4.** Per-repo dependency inventories, SBOM, vuln, secrets-risk. |
| `relationships.json` | **Phase 3.** Cross-repo/-module edges (typed, evidence-backed). |
| `architecture.mmd` / `data-flows.mmd` | Mermaid diagrams (compile-checked by validator). |
| `gaps-and-risks.md` | Duplication, dead code, rebuilt-elsewhere, hidden coupling, missing tests. |
| `unknowns.md` | Explicit open questions / unverified inferences. |
| `evidence/` | Raw findings preserved verbatim (gh JSON, rg dumps, scanner output). |
| `schema/fact.schema.json` | The fact-object contract. |
| `validate.py` | Machine check — fails on unsupported claims / structural defects. |
| `build_organization.py` | Regenerates `organization.yaml` from `evidence/gh-repo-list.json`. |
| `refresh.sh` | **Phase 6.** Re-run discovery + regenerate + validate. |

## Verify / refresh

```bash
python catalog/validate.py        # must exit 0
bash   catalog/refresh.sh         # re-discover + regenerate + validate
```

## Confidence taxonomy

- **confirmed** — grounded in code/config/git via a code-level `detection_method` (`rg`, `ls`, `file-read`, `ast-grep`, `gh-cli`, …). Must carry a `file`.
- **strong-inference** — supported but derived (e.g. a gh description, a single doc). Never used to assert a *code relationship* on its own (plan rule: never invent relationships from documentation alone).
- **unknown** — flagged for follow-up in `unknowns.md`.

98 repos. **3 production-critical** (`MIRA`, `factorylm`, `MIRA_PLC`), 8 active-supporting,
6 superseded, 4 documentation-only, 4 demo, 1 generated, **72 archived-experimental** (the
2026-03-03 "great archive": the merged-into-monolith cluster + the frozen Jarvis/PAI/openclaw/
Ralph experiments). Deep archaeology (Phase 2+) targets the active set; archived repos are
classified only.
